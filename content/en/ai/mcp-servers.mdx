## What is MCP?

The **Model Context Protocol (MCP)** is an open standard developed by Anthropic that defines how AI applications communicate with external tools and data sources. Think of it as a USB-C port for AI: a universal interface that allows any AI model to connect to any external service through a standardized protocol.

In the context of Claude Code, MCP servers are plugins that give Claude access to new tools beyond its built-in capabilities. Want Claude to query your database? Read your Jira tickets? Interact with your Kubernetes cluster? An MCP server makes it possible.

<Callout type="info">
MCP is an open protocol, not proprietary to Anthropic. Any AI application can implement MCP support, and any developer can build MCP servers. This creates an ecosystem of reusable tools that work across different AI platforms.
</Callout>

## How MCP Works

The MCP architecture follows a client-server model:

- **MCP Client**: Built into Claude Code, it discovers and communicates with MCP servers
- **MCP Server**: A lightweight process that exposes tools, resources, and prompts
- **Transport**: Communication happens over stdin/stdout (local servers) or HTTP with SSE (remote servers)

<Diagram chart="graph TD\n    A[Claude Code] --> B[MCP Client]\n    B -->|Initialize| C[MCP Server Process]\n    C -->|List Tools| B\n    B -->|Call Tool| C\n    C -->|Execute| D[External Service]\n    D -->|Response| C\n    C -->|Result| B\n    B -->|Feed to Agent| A" />

### The MCP Lifecycle

1. **Discovery**: Claude Code reads your configuration and starts the configured MCP servers
2. **Initialization**: Each server declares its available tools, resources, and capabilities
3. **Tool Registration**: Claude's agent becomes aware of the new tools and can use them
4. **Execution**: When the agent calls an MCP tool, the request is routed to the appropriate server
5. **Response**: The server processes the request and returns results to the agent

## Installing MCP Servers

### Configuration

MCP servers are configured in your Claude Code settings. You can add them at the project level or user level:

```json
// .claude/settings.json (project-level)
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": {
        "GITHUB_TOKEN": "your-token-here"
      }
    }
  }
}
```

Or add them via the CLI:

```bash
claude mcp add github npx -y @modelcontextprotocol/server-github
```

### Example: Adding a PostgreSQL Server

```bash
# Install and configure
claude mcp add postgres npx -y @modelcontextprotocol/server-postgres \
  --env POSTGRES_CONNECTION_STRING=postgresql://user:pass@localhost:5432/mydb
```

Now Claude Code can query your database directly:

```
> Show me the top 10 users by order count from the database

Claude will use the postgres MCP tools to run:
SELECT u.name, COUNT(o.id) as order_count
FROM users u
JOIN orders o ON u.id = o.user_id
GROUP BY u.name
ORDER BY order_count DESC
LIMIT 10;
```

<Callout type="warning">
Be careful when connecting MCP servers to production databases or services. Claude Code will have whatever access level the credentials you provide allow. Use read-only credentials where possible, and always prefer staging environments for testing.
</Callout>

## Building a Custom MCP Server

When no existing server meets your needs, you can build your own. MCP servers can be written in TypeScript, Python, or any language that can communicate over stdin/stdout.

### TypeScript MCP Server

Here is a complete example of a simple MCP server that provides weather data:

```typescript
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import { z } from "zod";

const server = new McpServer({
  name: "weather-server",
  version: "1.0.0",
});

// Define a tool
server.tool(
  "get-weather",
  "Get current weather for a city",
  {
    city: z.string().describe("City name"),
    units: z.enum(["celsius", "fahrenheit"]).default("celsius"),
  },
  async ({ city, units }) => {
    // Call a weather API
    const response = await fetch(
      `https://api.weatherapi.com/v1/current.json?key=${process.env.WEATHER_API_KEY}&q=${city}`
    );
    const data = await response.json();

    const temp = units === "celsius"
      ? data.current.temp_c
      : data.current.temp_f;

    return {
      content: [
        {
          type: "text",
          text: `Weather in ${city}: ${temp}° ${units}, ${data.current.condition.text}`,
        },
      ],
    };
  }
);

// Start the server
const transport = new StdioServerTransport();
await server.connect(transport);
```

### Python MCP Server

```python
from mcp.server import Server
from mcp.server.stdio import stdio_server
from mcp.types import Tool, TextContent
import json

server = Server("my-custom-server")

@server.list_tools()
async def list_tools():
    return [
        Tool(
            name="lookup-ticket",
            description="Look up a support ticket by ID",
            inputSchema={
                "type": "object",
                "properties": {
                    "ticket_id": {
                        "type": "string",
                        "description": "The ticket ID to look up"
                    }
                },
                "required": ["ticket_id"]
            }
        )
    ]

@server.call_tool()
async def call_tool(name: str, arguments: dict):
    if name == "lookup-ticket":
        ticket_id = arguments["ticket_id"]
        # Your lookup logic here
        ticket = await fetch_ticket(ticket_id)
        return [TextContent(
            type="text",
            text=json.dumps(ticket, indent=2)
        )]

async def main():
    async with stdio_server() as (read, write):
        await server.run(read, write)

if __name__ == "__main__":
    import asyncio
    asyncio.run(main())
```

## MCP Server Architecture Patterns

### Pattern 1: API Gateway

Wrap an existing REST API as an MCP server:

```typescript
server.tool("api-get", "Make GET request to internal API", {
  endpoint: z.string(),
  params: z.record(z.string()).optional(),
}, async ({ endpoint, params }) => {
  const url = new URL(endpoint, process.env.API_BASE_URL);
  if (params) {
    Object.entries(params).forEach(([k, v]) => url.searchParams.set(k, v));
  }
  const res = await fetch(url.toString(), {
    headers: { Authorization: `Bearer ${process.env.API_TOKEN}` },
  });
  return { content: [{ type: "text", text: await res.text() }] };
});
```

### Pattern 2: Database Abstraction

Provide safe, read-only database access:

```typescript
server.tool("query", "Run a read-only SQL query", {
  sql: z.string(),
}, async ({ sql }) => {
  // Safety check: only allow SELECT statements
  if (!sql.trim().toUpperCase().startsWith("SELECT")) {
    return {
      content: [{ type: "text", text: "Error: Only SELECT queries are allowed" }],
      isError: true,
    };
  }
  const result = await db.query(sql);
  return { content: [{ type: "text", text: JSON.stringify(result.rows, null, 2) }] };
});
```

### Pattern 3: Service Aggregator

Combine multiple services behind a single MCP server:

```typescript
// One server that wraps multiple services
server.tool("jira-get-issue", "Get Jira issue details", { key: z.string() }, ...);
server.tool("confluence-search", "Search Confluence pages", { query: z.string() }, ...);
server.tool("slack-post", "Post a message to Slack", { channel: z.string(), text: z.string() }, ...);
```

<Callout type="tip">
When building MCP servers for your team, focus on exposing high-level, task-oriented tools rather than raw API endpoints. Instead of "make HTTP GET request," provide "get user's recent orders." This gives the Claude agent better context about when and how to use each tool.
</Callout>

## Debugging MCP Servers

When an MCP server is not working as expected:

```bash
# Check server status
claude mcp list

# View server logs
claude mcp logs github

# Test a server independently
echo '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' | node ./tools/my-server/index.js
```

### Common Issues

1. **Server fails to start**: Check that the command path is correct and dependencies are installed
2. **Tools not appearing**: Verify the `list_tools` handler returns valid tool definitions
3. **Authentication errors**: Ensure environment variables are correctly set in the MCP config
4. **Timeout errors**: MCP servers should respond within 30 seconds; optimize slow operations

MCP servers transform Claude Code from a coding assistant into a universal development platform. By connecting it to your databases, APIs, issue trackers, and internal tools, you create an AI assistant that truly understands and can operate within your entire development ecosystem.
