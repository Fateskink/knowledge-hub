## The Three Layers of Claude Code

Claude Code is not a single monolithic tool. It is a carefully layered system where each layer has a distinct responsibility. Understanding these layers helps you work with Claude Code more effectively and unlocks the ability to build custom agentic workflows.

<Diagram chart="graph TD\n    A[CLI Layer] -->|User Input| B[Agent Layer]\n    B -->|Tool Calls| C[Tool Layer]\n    C -->|Results| B\n    B -->|Reasoning| B\n    B -->|Output| A\n    C --> D[Read Files]\n    C --> E[Write Files]\n    C --> F[Execute Shell]\n    C --> G[Search Code]\n    C --> H[MCP Servers]\n    C --> I[Web Fetch]" />

## Layer 1: The CLI

The CLI is your interface to Claude Code. It handles authentication, session management, input/output rendering, and permission prompts. When you type `claude` in your terminal, you are interacting with this layer.

### CLI Modes

The CLI supports several operational modes:

```bash
# Interactive REPL mode (default)
claude

# One-shot mode: single prompt, single response
claude -p "explain this function"

# Pipe mode: read from stdin
cat error.log | claude -p "what caused this error?"

# Continue mode: resume last conversation
claude --continue

# JSON output mode: structured output for scripting
claude -p "list all TODO comments" --output-format json
```

### What the CLI Does NOT Do

The CLI does not make decisions about what actions to take. It does not read files or execute commands. It is purely the interface layer, relaying your messages to the agent and rendering the agent's responses back to you.

<Callout type="info">
The CLI is responsible for the permission system. When the agent requests to execute a tool (like writing a file or running a command), the CLI intercepts the request and asks for your approval before proceeding.
</Callout>

## Layer 2: The Agent

The agent is the brain of Claude Code. It is an **agentic loop** powered by one of the Claude models. When you give it a task, the agent:

1. **Analyzes** the request and plans an approach
2. **Selects tools** to gather information or take action
3. **Processes results** from tool executions
4. **Iterates** until the task is complete or it needs your input
5. **Reports** the final outcome

### The Agent Loop

The agent operates in a continuous loop of reasoning and action. This is what makes Claude Code "agentic" rather than just a chatbot.

<Diagram chart="graph TD\n    A[Receive User Message] --> B[Reason About Task]\n    B --> C{Need More Info?}\n    C -->|Yes| D[Select Tool]\n    D --> E[Execute Tool]\n    E --> F[Process Result]\n    F --> B\n    C -->|No| G{Task Complete?}\n    G -->|No| D\n    G -->|Yes| H[Generate Response]\n    H --> I[Return to User]" />

Each iteration of this loop is called a **turn**. A single user request might trigger dozens of turns as the agent reads files, searches code, makes edits, and verifies its work.

### Agent Context

The agent maintains context throughout a conversation. This includes:

- **Conversation history**: All previous messages and responses
- **Tool results**: Output from file reads, command executions, and searches
- **System prompt**: Instructions that define Claude Code's behavior
- **CLAUDE.md contents**: Project-specific context from memory files

<Callout type="warning">
The agent's context grows with each turn. For long sessions, use `/compact` to compress the conversation history and free up context window space. This is especially important when using Sonnet or Haiku with their 200K token limit.
</Callout>

## Layer 3: The Tools

Tools are the agent's hands. They allow Claude to interact with the real world: your filesystem, your terminal, and external services. Each tool has a specific purpose and a defined interface.

### How Tools Work

When the agent decides to use a tool, it generates a **tool call** with specific parameters. The CLI intercepts this call, checks permissions, and either executes it or asks for your approval.

```json
{
  "tool": "Edit",
  "parameters": {
    "file_path": "/src/utils/auth.ts",
    "old_string": "const token = getToken();",
    "new_string": "const token = await getToken();"
  }
}
```

The tool executes and returns a result to the agent, which then incorporates it into its reasoning for the next step.

### Permission Model

Tools are categorized by their risk level:

- **Read-only tools** (Read, Glob, Grep): Generally allowed without prompting
- **Write tools** (Edit, Write): Require approval by default
- **Execute tools** (Bash): Require approval, with command review
- **Network tools** (WebFetch): Controlled by network permissions

You can configure permission profiles to automate approvals for trusted operations:

```bash
# Use permissive profile (auto-approve most operations)
claude --profile permissive

# Use default profile (ask for write/execute approval)
claude
```

## The Claude Code SDK

For developers who want to build custom agentic workflows, Anthropic provides the **Claude Code SDK**. This SDK exposes the same agent and tool infrastructure that powers the CLI, allowing you to embed Claude Code's capabilities in your own applications.

### SDK Installation

```bash
npm install @anthropic-ai/claude-code-sdk
```

### Basic Usage

```typescript
import { ClaudeCode } from "@anthropic-ai/claude-code-sdk";

const claude = new ClaudeCode({
  model: "claude-sonnet-4-20250514",
});

// Run a task programmatically
const result = await claude.run({
  prompt: "Find all functions that don't have error handling",
  workingDirectory: "/path/to/project",
});

console.log(result.output);
```

### Streaming Responses

The SDK supports streaming for real-time output:

```typescript
const stream = claude.stream({
  prompt: "Refactor the authentication module",
  workingDirectory: "/path/to/project",
});

for await (const event of stream) {
  if (event.type === "text") {
    process.stdout.write(event.content);
  } else if (event.type === "tool_use") {
    console.log(`Using tool: ${event.tool}`);
  }
}
```

### Custom Tool Integration

You can extend the agent with custom tools through MCP servers (covered in the MCP article) or by configuring tool permissions:

```typescript
const result = await claude.run({
  prompt: "Deploy the staging environment",
  tools: {
    allowedCommands: ["npm run deploy:staging", "kubectl apply"],
    blockedCommands: ["rm -rf", "drop table"],
  },
});
```

## Agent vs Tool vs CLI: When Does It Matter?

Understanding the separation of concerns matters in several scenarios:

### Debugging Issues

If Claude Code is not behaving as expected, knowing which layer is responsible helps you diagnose the problem:

- **CLI issues**: Authentication failures, rendering problems, permission denials
- **Agent issues**: Poor reasoning, wrong approach, missing context
- **Tool issues**: File read errors, command failures, permission problems

### Customization

Each layer can be customized differently:

- **CLI**: Configuration files, flags, profiles
- **Agent**: CLAUDE.md instructions, system prompts, model selection
- **Tools**: MCP servers, permission settings, allowed commands

### Extending Claude Code

When you want to add new capabilities:

- **Add a skill**: New prompt-based workflow (agent layer)
- **Add an MCP server**: New tools for the agent to use (tool layer)
- **Use the SDK**: Build entirely new interfaces (replace the CLI layer)

## Practical Architecture Example

Here is how a typical task flows through all three layers:

```
User types: "Add error handling to the payment service"

CLI Layer:
  → Captures input
  → Sends to agent with conversation context

Agent Layer (Turn 1):
  → Reasons: "I need to find the payment service file first"
  → Calls tool: Grep("PaymentService", "src/")

Tool Layer:
  → Executes grep, returns: "src/services/payment.ts:15"

Agent Layer (Turn 2):
  → Calls tool: Read("src/services/payment.ts")

Tool Layer:
  → Reads file, returns contents

Agent Layer (Turn 3):
  → Reasons: "I see functions without try-catch blocks"
  → Calls tool: Edit("src/services/payment.ts", changes...)

Tool Layer:
  → CLI prompts user for approval
  → User approves
  → Applies edit

Agent Layer (Turn 4):
  → Reasons: "Let me verify the changes compile"
  → Calls tool: Bash("npx tsc --noEmit")

Tool Layer:
  → Runs TypeScript compiler, returns success

Agent Layer (Final):
  → Generates summary of changes made

CLI Layer:
  → Renders response to terminal
```

This multi-turn, tool-assisted reasoning is what makes Claude Code an agent rather than a simple code generator. Each layer plays its role, and together they enable complex, autonomous development workflows.
