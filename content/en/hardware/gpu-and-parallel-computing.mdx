# GPU and Parallel Computing: Why Graphics Cards Power the AI Revolution

Graphics Processing Units were originally designed for one thing: rendering the millions of pixels on your screen fast enough to produce smooth images. But the same architectural features that make GPUs excellent at graphics — thousands of small cores working in parallel — turned out to be exactly what artificial intelligence and scientific computing needed. Today, GPUs are the engines driving the AI revolution, and understanding why requires understanding the fundamental difference between how CPUs and GPUs approach computation.

<Callout type="info">
Training GPT-4 reportedly required around 25,000 NVIDIA A100 GPUs running for approximately 90-100 days. Without GPUs, training modern large language models would be practically impossible — it would take hundreds of years on conventional CPUs.
</Callout>

## CPU vs. GPU: Two Different Philosophies

A CPU is designed to handle a wide variety of tasks as quickly as possible — one (or a few) at a time. It has a small number of powerful cores optimized for sequential processing, with large caches and sophisticated control logic for branch prediction, out-of-order execution, and speculative execution.

A GPU takes the opposite approach. It has thousands of simpler cores designed to perform the same operation on many pieces of data simultaneously. It sacrifices single-threaded performance for massive parallelism.

Think of it this way: a CPU is like a sports car — incredibly fast on a straight road, but it only carries one passenger. A GPU is like a bus — slower per trip, but it moves thousands of passengers at once.

## Inside a Modern GPU

### Streaming Multiprocessors (SMs)

A GPU is organized into an array of Streaming Multiprocessors (SMs), each containing multiple types of processing cores. An NVIDIA RTX 4090, for example, has 128 SMs, each with 128 CUDA cores, 4 Tensor cores, and 1 RT core.

<Diagram chart="graph TD\n    subgraph GPU[GPU Die]\n        subgraph SM1[Streaming Multiprocessor]\n            CUDA1[128 CUDA Cores\nGeneral parallel computation]\n            TENSOR1[4 Tensor Cores\nMatrix multiply-accumulate]\n            RT1[1 RT Core\nRay tracing acceleration]\n            L1_1[L1 Cache / Shared Memory]\n            SCHED1[Warp Scheduler]\n        end\n        subgraph SM2[SM 2]\n            CUDA2[128 CUDA Cores]\n            TENSOR2[4 Tensor Cores]\n            RT2[1 RT Core]\n        end\n        L2[L2 Cache - Shared across all SMs]\n        MC[Memory Controllers]\n    end\n    MC <--> VRAM[GDDR6X or HBM VRAM]" />

### CUDA Cores

CUDA (Compute Unified Device Architecture) cores are NVIDIA's basic parallel processing units. Each CUDA core can perform one floating-point or integer operation per clock cycle. The power of a GPU comes not from any individual core being fast, but from thousands of them working simultaneously.

When a GPU processes an image, for example, it does not process each pixel one at a time. Instead, it assigns different pixels to different cores, and thousands of pixels are processed in the same clock cycle.

### Tensor Cores

Tensor cores are specialized hardware units designed specifically for matrix multiplication — the mathematical operation at the heart of neural network training and inference. A single Tensor core can perform a 4x4 matrix multiply-and-accumulate in one clock cycle, an operation that would take a CUDA core many cycles.

<Diagram chart="graph LR\n    subgraph Matrix_Op[Tensor Core Operation]\n        A[Matrix A\n4x4] --> TC[Tensor Core]\n        B[Matrix B\n4x4] --> TC\n        C[Matrix C\nAccumulator] --> TC\n        TC --> D[Result D = A x B + C\nOne clock cycle]\n    end" />

NVIDIA's H100 GPU contains 528 Tensor cores that collectively deliver nearly 2,000 teraflops of AI performance using FP8 precision — that is 2 quadrillion operations per second.

<Callout type="tip">
Tensor cores support multiple precision levels: FP64, TF32, FP16, BF16, INT8, and FP8. Lower precision means faster computation with acceptable accuracy loss for many AI workloads. This is why AI inference often uses FP16 or INT8 — it is much faster than FP32 with minimal quality impact.
</Callout>

### VRAM (Video RAM)

VRAM is the GPU's dedicated memory. Unlike system RAM, VRAM is optimized for bandwidth rather than latency, because GPUs need to feed thousands of cores simultaneously.

Modern high-end GPUs use two types of VRAM:
- **GDDR6X:** Used in gaming GPUs (e.g., RTX 4090 with 24 GB GDDR6X at 1,008 GB/s bandwidth).
- **HBM (High Bandwidth Memory):** Used in data center GPUs (e.g., H100 with 80 GB HBM3 at 3,350 GB/s bandwidth). HBM stacks memory dies vertically and uses wide interfaces for enormous bandwidth.

<Callout type="warning">
VRAM is often the bottleneck for AI workloads. A large language model must fit entirely in VRAM during inference (or be split across multiple GPUs). A 70-billion parameter model at FP16 precision requires approximately 140 GB of VRAM — more than any single consumer GPU provides. This is why large model deployment typically requires multiple high-end data center GPUs.
</Callout>

## Why GPUs Matter for AI and Machine Learning

Neural network training and inference are dominated by one operation: matrix multiplication. Training a neural network involves:

1. **Forward pass:** Multiply input data by weight matrices through each layer.
2. **Loss calculation:** Compare the output to the expected result.
3. **Backward pass (backpropagation):** Compute gradients through matrix operations.
4. **Weight update:** Adjust weights using the gradients.

Every one of these steps involves massive matrix operations on large batches of data — exactly the kind of highly parallel, uniform computation that GPUs excel at.

A task that would take a 32-core CPU server weeks to complete can be finished by a cluster of GPUs in hours. This is not a small speedup — it is the difference between feasible and infeasible for large-scale AI research.

## NVIDIA vs. AMD vs. Apple: The GPU Landscape

### NVIDIA

NVIDIA dominates the AI/ML GPU market with an estimated 80-95% market share in data center AI accelerators. Their advantage comes from three pillars:

- **Hardware:** Tensor cores, HBM memory, NVLink interconnects for multi-GPU communication.
- **CUDA ecosystem:** The CUDA programming model, cuDNN library, and TensorRT inference engine have been the standard for over 15 years. Nearly all AI frameworks (PyTorch, TensorFlow) are optimized for CUDA.
- **Full-stack approach:** NVIDIA provides the GPU, the networking (InfiniBand/NVLink), the software stack, and even the reference server designs (DGX).

Key products: H100 and H200 (data center AI), RTX 4090/5090 (consumer/prosumer), Grace Hopper Superchip (CPU+GPU integrated).

### AMD

AMD has been aggressively competing in the GPU space:

- **Instinct MI300X:** AMD's data center AI GPU with 192 GB of HBM3 memory — more than double the H100's 80 GB. This large memory pool is attractive for running very large models.
- **RDNA architecture:** Powers consumer Radeon GPUs, competitive with NVIDIA in gaming.
- **ROCm:** AMD's open-source alternative to CUDA. While improving, the ROCm ecosystem is still less mature than CUDA, which remains AMD's biggest challenge in AI adoption.

### Apple Silicon

Apple took a radically different approach with its M-series chips by integrating the CPU, GPU, Neural Engine, and unified memory on a single die.

<Diagram chart="graph TD\n    subgraph Apple[Apple M-Series SoC]\n        CPU_A[CPU Cores\nP-cores + E-cores]\n        GPU_A[GPU Cores\nUp to 40 cores]\n        NE[Neural Engine\n16 cores, 38 TOPS]\n        UM[Unified Memory\nShared by CPU + GPU\nUp to 192 GB]\n        ME[Media Engine\nVideo encode/decode]\n        ISP[Image Signal Processor]\n    end\n    CPU_A <--> UM\n    GPU_A <--> UM\n    NE <--> UM" />

The key innovation is unified memory architecture (UMA) — the CPU and GPU share the same physical memory pool. Data does not need to be copied between CPU RAM and GPU VRAM. For AI workloads that involve moving large amounts of data between CPU and GPU, this eliminates a significant bottleneck.

Apple's M4 Max with 128 GB of unified memory can run large language models locally that would require an expensive discrete GPU on other platforms. However, Apple's ML ecosystem is less mature, and the memory bandwidth (400 GB/s) is far below dedicated AI GPUs like the H100 (3,350 GB/s).

<Callout type="info">
The GPU landscape is evolving rapidly. New entrants like Intel (Gaudi accelerators), Google (TPUs), Amazon (Trainium/Inferentia), and startups like Cerebras (wafer-scale chips) and Groq (LPU inference chips) are challenging NVIDIA's dominance with architectures specifically designed for AI workloads rather than adapted from graphics processors.
</Callout>

## GPGPU: General-Purpose Computing on GPUs

The use of GPUs for non-graphics computation is called GPGPU (General-Purpose GPU computing). Beyond AI, GPUs accelerate:

- **Scientific simulation:** Molecular dynamics, climate modeling, fluid dynamics.
- **Cryptocurrency mining:** SHA-256 and Ethash hashing (though this has decreased post-Ethereum's move to proof-of-stake).
- **Video processing:** Encoding, decoding, and real-time video effects.
- **Financial modeling:** Monte Carlo simulations, risk analysis.
- **Medical imaging:** CT and MRI reconstruction, computational pathology.

## Programming GPUs: The Software Side

Writing software for GPUs requires thinking differently. Instead of sequential algorithms, you write kernels — functions that are executed by thousands of threads simultaneously.

In CUDA (NVIDIA's programming model), you define a kernel function and specify how many threads to launch. The GPU runtime distributes these threads across its SMs. Each thread executes the same code but on different data — a model called SIMT (Single Instruction, Multiple Threads).

The challenge is that not all problems parallelize well. Tasks with heavy data dependencies, unpredictable branching, or sequential logic are poor fits for GPUs. The art of GPU programming lies in restructuring problems to maximize parallelism and minimize memory access bottlenecks.

The GPU's journey from a specialized graphics chip to the most important hardware platform in AI is one of the most consequential technology shifts of the 21st century. Understanding GPU architecture is no longer just for game developers or graphics programmers — it is essential knowledge for anyone working in AI, scientific computing, or high-performance systems.
