# TCP/IP and Networking

Every time you visit a website, send an email, or stream a video, your data travels through multiple layers of network protocols. TCP/IP is the foundational protocol suite of the Internet, enabling computers to communicate reliably across the globe.

## The TCP/IP Model

The TCP/IP model consists of 4 layers, each handling a specific function:

<Diagram chart="graph TD\n    subgraph TCP/IP Model\n    A[Application Layer\nHTTP, HTTPS, FTP, DNS, SMTP] --> B[Transport Layer\nTCP, UDP]\n    B --> C[Internet Layer\nIP, ICMP, ARP]\n    C --> D[Network Access Layer\nEthernet, Wi-Fi, Fiber]\n    end" />

### Layer 1: Network Access Layer

The lowest layer handles physical data transmission over the network medium (Ethernet cables, Wi-Fi, fiber optics). It includes protocols like Ethernet, Wi-Fi (802.11), and hardware drivers.

### Layer 2: Internet Layer

This layer is responsible for routing -- determining the path data takes from source to destination across multiple networks.

- **IP (Internet Protocol)**: Assigns addresses to devices and routes packets
- **ICMP**: Used for network diagnostics (ping, traceroute)
- **ARP**: Maps IP addresses to physical MAC addresses

```bash
# View your machine's IP address
ip addr show        # Linux
ifconfig            # macOS
ipconfig            # Windows

# Check network connectivity
ping google.com

# Trace the path of packets
traceroute google.com    # Linux/macOS
tracert google.com       # Windows
```

### Layer 3: Transport Layer

This layer ensures data is transmitted reliably (TCP) or quickly (UDP) between two applications.

### Layer 4: Application Layer

The highest layer provides protocols for applications: HTTP for the web, SMTP for email, FTP for file transfer, DNS for domain name resolution.

## TCP vs UDP

TCP (Transmission Control Protocol) and UDP (User Datagram Protocol) are the two main transport protocols.

### TCP -- Reliable

TCP ensures data is delivered completely and in order. Before sending data, TCP establishes a connection through a 3-way handshake:

<Diagram chart="graph LR\n    A[Client] -->|1. SYN| B[Server]\n    B -->|2. SYN-ACK| A\n    A -->|3. ACK| B\n    A <-->|Data Transfer| B\n    A -->|FIN| B\n    B -->|ACK + FIN| A\n    A -->|ACK| B" />

1. **SYN**: Client sends a connection request
2. **SYN-ACK**: Server acknowledges and agrees to connect
3. **ACK**: Client confirms receipt, connection is established

```python
# TCP server example with Python
import socket

# Create a TCP socket
server = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
server.bind(('0.0.0.0', 8080))
server.listen(5)
print('Server listening on port 8080...')

while True:
    client_socket, address = server.accept()
    print(f'New connection from {address}')

    data = client_socket.recv(1024)
    print(f'Received: {data.decode()}')

    client_socket.send(b'Data received successfully!')
    client_socket.close()
```

### UDP -- Fast

UDP sends data without establishing a connection first. It does not guarantee delivery or ordering, but is much faster than TCP.

```python
# UDP server example
import socket

udp_server = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
udp_server.bind(('0.0.0.0', 9090))
print('UDP server listening...')

while True:
    data, addr = udp_server.recvfrom(1024)
    print(f'Received from {addr}: {data.decode()}')
    udp_server.sendto(b'Pong!', addr)
```

## DNS -- Domain Name System

DNS translates domain names (e.g., google.com) into IP addresses (e.g., 142.250.80.46) so computers can connect.

<Diagram chart="graph LR\n    A[Browser\ngoogle.com?] --> B[DNS Resolver\nISP Cache]\n    B --> C[Root Name Server\n. root]\n    C --> D[TLD Name Server\n.com]\n    D --> E[Authoritative Server\ngoogle.com]\n    E -->|142.250.80.46| B\n    B -->|142.250.80.46| A" />

```bash
# DNS lookup
nslookup google.com

# Detailed DNS record information
dig google.com

# Common DNS record types
dig google.com A       # IPv4 address
dig google.com AAAA    # IPv6 address
dig google.com MX      # Mail server
dig google.com CNAME   # Alias
dig google.com TXT     # Text record (SPF, DKIM)
```

## HTTP and HTTPS

HTTP (HyperText Transfer Protocol) is the primary protocol for transferring data on the web.

### HTTP Request Structure

```
GET /api/users HTTP/1.1
Host: example.com
Accept: application/json
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
```

### HTTP Response Structure

```
HTTP/1.1 200 OK
Content-Type: application/json
Content-Length: 128

{"users": [{"id": 1, "name": "User A"}]}
```

### Common HTTP Methods

| Method | Purpose | Idempotent |
|--------|---------|------------|
| GET | Retrieve data | Yes |
| POST | Create new data | No |
| PUT | Full update | Yes |
| PATCH | Partial update | No |
| DELETE | Remove data | Yes |

### HTTPS -- Secure HTTP

HTTPS uses TLS/SSL to encrypt data transmitted between client and server:

<Diagram chart="graph LR\n    A[Client] -->|1. Client Hello| B[Server]\n    B -->|2. Server Hello + Certificate| A\n    A -->|3. Verify Certificate\nCreate Session Key| A\n    A -->|4. Encrypted Data| B\n    B -->|5. Encrypted Data| A" />

<Callout type="warning">Always use HTTPS for every web application, especially when handling sensitive data like passwords and payment information. HTTPS not only encrypts data but also verifies the server's identity, preventing man-in-the-middle attacks.</Callout>

## HTTP/2 and HTTP/3

### HTTP/2
- **Multiplexing**: Multiple requests/responses simultaneously over a single TCP connection
- **Header Compression**: Reduces header size with HPACK
- **Server Push**: Server can send resources before the client requests them

### HTTP/3
- Uses **QUIC** (over UDP) instead of TCP
- Reduces connection establishment time
- Better for unstable networks (mobile, public Wi-Fi)

<Callout type="tip">Most modern web servers and CDNs support HTTP/2. HTTP/3 is gaining widespread support. You can check the protocol in use via your browser's Developer Tools (Network tab, Protocol column).</Callout>

## Practical Example: Anatomy of a Web Request

When you type `https://example.com` into your browser, here is what happens:

1. **DNS Resolution**: The browser asks a DNS server for the IP address of example.com
2. **TCP Handshake**: Establishes a TCP 3-way handshake with the server
3. **TLS Handshake**: Establishes an encrypted TLS/SSL connection
4. **HTTP Request**: Sends an HTTP GET request to the server
5. **Server Processing**: The server processes the request and returns a response
6. **Rendering**: The browser receives HTML, loads CSS/JS, and renders the page

```javascript
// Measure the timing of each phase
const timing = performance.getEntriesByType('navigation')[0];

console.log('DNS lookup:', timing.domainLookupEnd - timing.domainLookupStart, 'ms');
console.log('TCP connect:', timing.connectEnd - timing.connectStart, 'ms');
console.log('TLS handshake:', timing.secureConnectionStart > 0
  ? timing.connectEnd - timing.secureConnectionStart : 'N/A', 'ms');
console.log('Request + Response:', timing.responseEnd - timing.requestStart, 'ms');
console.log('DOM loaded:', timing.domContentLoadedEventEnd - timing.navigationStart, 'ms');
```
