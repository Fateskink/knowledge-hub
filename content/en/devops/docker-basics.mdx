# Docker Basics

Docker is an open-source platform that enables you to package, distribute, and run applications inside containers. Instead of manually configuring complex environments on each machine, Docker lets you create isolated, consistent environments that can be reproduced on any system. This article will help you understand the core concepts of Docker and start using it effectively.

## What Is a Container?

A container is a lightweight, standalone unit of software that includes everything needed to run an application: source code, libraries, system tools, and configuration. Containers share the host operating system's kernel, making them far lighter than traditional virtual machines.

### Containers vs Virtual Machines

| Criteria | Containers | Virtual Machines |
|----------|-----------|-----------------|
| Size | Megabytes | Gigabytes |
| Startup time | Seconds | Minutes |
| Performance | Near native | Has overhead |
| Isolation | Process level | OS level |
| RAM usage | Low | High |
| Portability | Very high | Medium |

<Callout type="info">Containers do not fully replace virtual machines. Each is suited for different use cases. Containers are ideal for microservices, while VMs are better when you need complete OS-level isolation.</Callout>

## Core Docker Concepts

<Diagram chart="graph TD\n    A[Dockerfile] -->|docker build| B[Docker Image]\n    B -->|docker run| C[Docker Container]\n    B -->|docker push| D[Docker Registry]\n    D -->|docker pull| B\n    C -->|docker commit| B" />

### Docker Image

An image is the blueprint of a container. It contains the base operating system, application source code, libraries, and configuration. Images are immutable -- once built, they cannot be changed.

### Docker Container

A container is a running instance of an image. You can create multiple containers from the same image, and each operates independently.

### Dockerfile

A Dockerfile is a text file containing instructions for building a Docker image.

### Docker Registry

A registry is a storage and distribution system for Docker images. Docker Hub is the most popular public registry.

```bash

```

## Essential Docker Commands

```bash
# Pull an image from Docker Hub
docker pull nginx

# List downloaded images
docker images

# Run a container
docker run -d --name webserver -p 8080:80 nginx

# List running containers
docker ps

# List all containers (including stopped)
docker ps -a

# View container logs
docker logs webserver

# Execute a command inside a container
docker exec -it webserver bash

# Stop a container
docker stop webserver

# Remove a container
docker rm webserver

# Remove an image
docker rmi nginx
```

### Understanding docker run


## Writing a Dockerfile

A Dockerfile defines the environment for your application. Here is an example for a Node.js application.

```dockerfile
# Use Node.js as the base image
FROM node:20-alpine

# Set the working directory inside the container
WORKDIR /app

# Copy package files and install dependencies
COPY package*.json ./
RUN npm ci --only=production

# Copy application source code
COPY . .

# Declare the port the app will listen on
EXPOSE 3000

# Create a non-root user for security
RUN addgroup -S appgroup && adduser -S appuser -G appgroup
USER appuser

# Command to run when the container starts
CMD ["node", "server.js"]
```

### Python Flask Dockerfile Example

```dockerfile
FROM python:3.12-slim

WORKDIR /app

# Install dependencies first to leverage Docker cache
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY . .

EXPOSE 5000

# Use Gunicorn for production
CMD ["gunicorn", "--bind", "0.0.0.0:5000", "--workers", "4", "app:app"]
```

### Building and Running Your Image

```bash
# Build an image from the Dockerfile
docker build -t my-app:1.0 .

# Run a container from the newly built image
docker run -d --name my-app -p 3000:3000 my-app:1.0

# Test the application
curl http://localhost:3000
```

<Callout type="warning">Always use a .dockerignore file to prevent unnecessary files from being copied into the image (such as node_modules, .git, .env). This keeps images smaller and more secure.</Callout>

```text
# .dockerignore
node_modules
.git
.gitignore
.env
*.md
docker-compose*.yml
.dockerignore
Dockerfile
```

## Docker Compose

Docker Compose lets you define and manage multiple containers simultaneously using a single YAML file. It is the ideal tool for applications with multiple components such as a web server, database, and cache.

### Example: Web Application with Database

```yaml
# docker-compose.yml
version: "3.8"

services:
  # Web application
  web:
    build: .
    ports:
      - "3000:3000"
    environment:
      - DATABASE_URL=postgres://user:password@db:5432/myapp
      - REDIS_URL=redis://cache:6379
    depends_on:
      db:
        condition: service_healthy
      cache:
        condition: service_started
    restart: unless-stopped

  # PostgreSQL Database
  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: user
      POSTGRES_PASSWORD: password
      POSTGRES_DB: myapp
    volumes:
      - postgres_data:/var/lib/postgresql/data
    ports:
      - "5432:5432"
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U user -d myapp"]
      interval: 5s
      timeout: 5s
      retries: 5

  # Redis Cache
  cache:
    image: redis:7-alpine
    ports:
      - "6379:6379"
    volumes:
      - redis_data:/data

volumes:
  postgres_data:
  redis_data:
```

### Essential Docker Compose Commands

```bash
# Start all services
docker compose up -d

# View service status
docker compose ps

# View logs for all services
docker compose logs -f

# View logs for a specific service
docker compose logs -f web

# Stop all services
docker compose down

# Stop and remove volumes (destroys data!)
docker compose down -v

# Rebuild and restart
docker compose up -d --build
```

<Callout type="tip">Use `docker compose up -d --build` when you have changed your code or Dockerfile. The `--build` flag forces a rebuild of the image before starting the container.</Callout>

## Best Practices

### 1. Use Multi-Stage Builds

Multi-stage builds significantly reduce image size:

```dockerfile
# Stage 1: Build
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# Stage 2: Production
FROM node:20-alpine
WORKDIR /app
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/node_modules ./node_modules
EXPOSE 3000
CMD ["node", "dist/server.js"]
```

### 2. Key Guidelines

- **One process per container**: Each container should run a single main process.
- **Use specific tags**: Use `node:20-alpine` instead of `node:latest` to ensure consistency.
- **Never store secrets in images**: Use environment variables or Docker secrets.
- **Leverage layer caching**: Place infrequently changing instructions (like installing dependencies) before frequently changing ones (like copying source code).
- **Use Alpine images**: Alpine Linux-based images are much smaller than full-sized alternatives.

<Callout type="warning">Never store passwords, API keys, or sensitive information in your Dockerfile or image. Use environment variables or secrets management tools like Docker Secrets or HashiCorp Vault.</Callout>
