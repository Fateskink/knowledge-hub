# Docker Basics - From Concepts to Your First Container

"It works on my machine!" — If you have ever heard (or said) this, Docker is the solution. Docker is an open-source platform that lets you package an application along with its entire environment into a unit called a **container**, ensuring it runs consistently on any system — from your dev laptop to production servers.

This article will take you from core concepts to running your first container.

## What Is a Container?

A container is a lightweight unit of software that includes everything needed to run an application: source code, libraries, system tools, and configuration. The key difference from virtual machines (VMs): containers **share the host OS kernel**, so they start in seconds and consume very few resources.

<Callout type="info">Containers and VMs are not mutually exclusive. In practice, many systems run Docker **inside** VMs. Containers are ideal for microservices and CI/CD, while VMs are better when you need complete OS-level isolation.</Callout>

## Docker Architecture

Docker follows a **client-server** model with three main components:

<Diagram chart="graph LR\n    A[Docker Client\n docker CLI] -->|REST API| B[Docker Daemon\n dockerd]\n    B --> C[Images]\n    B --> D[Containers]\n    B --> E[Networks]\n    B --> F[Volumes]\n    B <-->|pull/push| G[Docker Registry\n Docker Hub]" />

### Docker Daemon (dockerd)

A background process that manages all Docker objects: images, containers, networks, and volumes. The daemon listens for requests from the Docker Client via REST API.

### Docker Client (docker)

The command-line tool you use daily. When you type `docker run`, the client sends the command to the daemon for execution.

### Docker Registry

A storage and distribution system for Docker images. **Docker Hub** is the largest public registry, hosting millions of ready-to-use images. You can also set up a private registry for your organization.

## Core Concepts

<Diagram chart="graph TD\n    A[Dockerfile] -->|docker build| B[Image]\n    B -->|docker run| C[Container]\n    B -->|docker push| D[Registry]\n    D -->|docker pull| B" />

### Image

An image is an **immutable blueprint** of a container. It is built from multiple layers stacked on top of each other — each instruction in a Dockerfile creates a new layer. When you change a layer, only that layer and those above it need to be rebuilt.

### Container

A container is a **running instance** of an image. You can create multiple containers from the same image, each operating independently with its own filesystem.

### Dockerfile

A text file containing a set of instructions for building an image. It is the "recipe" that tells Docker how to package your application.

### Volume

A mechanism for persistent data storage. Data inside a container is lost when the container is removed, but volumes preserve important data such as databases.

## Installing Docker

### macOS / Windows

Download and install **Docker Desktop** — it includes Docker Engine, CLI, Compose, and a graphical interface.

```bash
# Download from: https://www.docker.com/products/docker-desktop/
# After installation, verify:
docker --version
# Docker version 29.x.x
```

### Ubuntu / Debian

```bash
# Install Docker Engine
sudo apt-get update
sudo apt-get install docker-ce docker-ce-cli containerd.io docker-compose-plugin

# Allow your user to run Docker without sudo
sudo usermod -aG docker $USER
# Log out and log back in for the change to take effect

# Verify installation
docker --version
docker run hello-world
```

<Callout type="tip">The `docker run hello-world` command pulls the `hello-world` image from Docker Hub and runs it. If you see a welcome message, Docker is working.</Callout>

## Hands-on: Your First Container

Let's run an Nginx web server in a container:

```bash
# Step 1: Pull the nginx image from Docker Hub
docker pull nginx

# Step 2: Run a container
docker run -d --name webserver -p 8080:80 nginx
```

Open your browser at `http://localhost:8080` — you should see the Nginx welcome page.

### Understanding docker run

```bash
docker run -d --name webserver -p 8080:80 -v ./html:/usr/share/nginx/html nginx
#          │   │                │           │                                 │
#          │   │                │           │                                 └─ Image
#          │   │                │           └─ Mount local directory into container
#          │   │                └─ Map port: host 8080 → container 80
#          │   └─ Name the container
#          └─ Run in background (detached mode)
```

### Container Management Commands

```bash
# List running containers
docker ps

# List all containers (including stopped)
docker ps -a

# View logs
docker logs webserver

# Access a running container
docker exec -it webserver bash

# Stop a container
docker stop webserver

# Start it again
docker start webserver

# Remove a container (must stop first)
docker stop webserver && docker rm webserver
```

### Image Management

```bash
# List downloaded images
docker images

# Pull a specific image
docker pull node:22-alpine

# Remove an image
docker rmi nginx
```

## Writing Your First Dockerfile

Let's containerize a simple Node.js application:

```dockerfile
# Base image — Alpine Linux keeps the image small (~50MB vs ~300MB)
FROM node:22-alpine

# Set the working directory inside the container
WORKDIR /app

# Copy package files first to leverage Docker layer cache
# If dependencies haven't changed, this layer is cached → faster builds
COPY package*.json ./
RUN npm ci --omit=dev

# Copy source code (after dependencies to leverage cache)
COPY . .

# Declare the port the app listens on
EXPOSE 3000

# Create a non-root user — basic security practice
RUN addgroup -S appgroup && adduser -S appuser -G appgroup
USER appuser

# Command to run when the container starts
CMD ["node", "server.js"]
```

<Callout type="warning">Always create a `.dockerignore` file to keep unnecessary files out of the image. This makes images smaller, builds faster, and improves security.</Callout>

```text
# .dockerignore
node_modules
.git
.env
*.md
Dockerfile
```

### Build and Run

```bash
# Build the image with tag my-app version 1.0
docker build -t my-app:1.0 .

# Run a container from the newly built image
docker run -d --name my-app -p 3000:3000 my-app:1.0

# Test the application
curl http://localhost:3000
```

## Docker Compose — Running Multiple Containers

Real-world applications usually need multiple components: a web server, database, and cache. **Docker Compose** lets you define and manage all of them in a single `compose.yaml` file.

<Callout type="info">Docker Compose v5 (the current version) no longer requires the `version` field in compose files. The recommended filename is `compose.yaml` instead of `docker-compose.yml`.</Callout>

### Example: Web App + PostgreSQL + Redis

```yaml
# compose.yaml
services:
  # Web application
  web:
    build: .
    ports:
      - "3000:3000"
    environment:
      - DATABASE_URL=postgres://user:password@db:5432/myapp
      - REDIS_URL=redis://cache:6379
    depends_on:
      db:
        condition: service_healthy
      cache:
        condition: service_started
    restart: unless-stopped

  # PostgreSQL
  db:
    image: postgres:17-alpine
    environment:
      POSTGRES_USER: user
      POSTGRES_PASSWORD: password
      POSTGRES_DB: myapp
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U user -d myapp"]
      interval: 5s
      timeout: 5s
      retries: 5

  # Redis
  cache:
    image: redis:7-alpine
    volumes:
      - redis_data:/data

volumes:
  postgres_data:
  redis_data:
```

### Common Compose Commands

```bash
# Start all services (build if needed)
docker compose up -d

# View status
docker compose ps

# View logs in real time
docker compose logs -f

# Logs for a specific service
docker compose logs -f web

# Stop all services
docker compose down

# Stop and remove volumes (⚠️ destroys data!)
docker compose down -v

# Rebuild when code changes
docker compose up -d --build
```
