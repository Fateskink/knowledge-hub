# So sánh Models: Opus 4.6, Sonnet 4.6, và Haiku 4.5

## Tổng quan về các Model Claude

Anthropic cung cấp ba dòng model Claude với các đặc điểm khác nhau, phục vụ các nhu cầu sử dụng đa dạng trong Claude Code. Việc chọn đúng model cho từng tác vụ giúp bạn cân bằng giữa **chất lượng output**, **tốc độ phản hồi**, và **chi phí sử dụng**.

<Callout type="info" title="Chuyển model trong Claude Code">
Bạn có thể chuyển đổi model bất kỳ lúc nào trong phiên làm việc bằng lệnh `/model` hoặc flag `--model` khi khởi chạy. Claude Code mặc định sử dụng Sonnet cho hầu hết các tác vụ.
</Callout>

## Ba dòng Model

### Claude Opus 4.6 - Mạnh nhất

Opus 4.6 là model hàng đầu của Anthropic, được thiết kế cho các tác vụ đòi hỏi suy luận phức tạp, phân tích sâu, và đưa ra quyết định tinh tế. Đây là model được chọn khi chất lượng là ưu tiên hàng đầu.

**Điểm mạnh:**
- Suy luận logic và phân tích kiến trúc vượt trội
- Xử lý các bài toán multi-step phức tạp
- Hiểu context lớn với cửa sổ lên đến 1 triệu tokens
- Extended thinking cho phép suy nghĩ sâu trước khi trả lời
- Khả năng viết code chất lượng cao với ít lỗi nhất

### Claude Sonnet 4.6 - Cân bằng

Sonnet 4.6 là model cân bằng tốt nhất giữa hiệu năng và chi phí. Đây là lựa chọn mặc định trong Claude Code và phù hợp cho phần lớn các tác vụ lập trình hàng ngày.

**Điểm mạnh:**
- Tốc độ phản hồi nhanh hơn Opus đáng kể
- Chất lượng code generation rất tốt cho hầu hết use cases
- Chi phí hợp lý cho sử dụng thường xuyên
- Hỗ trợ extended thinking
- Cửa sổ context 200K tokens

### Claude Haiku 4.5 - Nhanh và tiết kiệm

Haiku 4.5 là model nhỏ nhất và nhanh nhất, lý tưởng cho các tác vụ đơn giản cần phản hồi tức thì với chi phí tối thiểu.

**Điểm mạnh:**
- Tốc độ phản hồi cực nhanh
- Chi phí thấp nhất trong ba model
- Phù hợp cho autocomplete, quick fixes, và các tác vụ đơn giản
- Cửa sổ context 200K tokens

## Khi nào dùng Model nào?

<Diagram chart="graph TD\n    A[Tác vụ cần thực hiện] --> B{Độ phức tạp?}\n    B -->|Cao| C{Budget cho phép?}\n    B -->|Trung bình| F[Sonnet 4.6]\n    B -->|Thấp| G[Haiku 4.5]\n    C -->|Có| D[Opus 4.6]\n    C -->|Hạn chế| F\n    D --> D1[Thiết kế kiến trúc]\n    D --> D2[Debug phức tạp]\n    D --> D3[Refactoring toàn bộ]\n    D --> D4[Code review quan trọng]\n    F --> F1[Feature development]\n    F --> F2[Viết tests]\n    F --> F3[Bug fixes thông thường]\n    F --> F4[Documentation]\n    G --> G1[Quick fixes]\n    G --> G2[Rename/format]\n    G --> G3[Simple queries]\n    G --> G4[Giải thích ngắn]" />

### Dùng Opus 4.6 khi:

1. **Thiết kế kiến trúc hệ thống** - Cần phân tích toàn diện và đưa ra quyết định kiến trúc phức tạp
2. **Debug lỗi khó** - Lỗi liên quan đến race conditions, memory leaks, hoặc logic phức tạp
3. **Refactoring quy mô lớn** - Di chuyển từ monolith sang microservices, đổi framework
4. **Code review quan trọng** - Review trước khi merge vào production
5. **Viết code cho hệ thống critical** - Payment processing, security, data integrity

```bash
# Chuyển sang Opus cho tác vụ phức tạp
> /model opus

# Hoặc khởi chạy với Opus
claude --model claude-opus-4-6
```

### Dùng Sonnet 4.6 khi:

1. **Phát triển tính năng hàng ngày** - CRUD operations, UI components, API endpoints
2. **Viết unit tests và integration tests** - Test coverage cho existing code
3. **Bug fixes thông thường** - Lỗi rõ ràng, có stack trace
4. **Documentation** - Viết comments, README, API docs
5. **Tác vụ agentic thông thường** - File operations, search, git tasks

```bash
# Sonnet là mặc định, nhưng bạn có thể chỉ định rõ
> /model sonnet

# Hoặc
claude --model claude-sonnet-4-6
```

### Dùng Haiku 4.5 khi:

1. **Quick fixes** - Sửa typo, thêm import, fix syntax errors
2. **Các câu hỏi đơn giản** - "File này làm gì?", "Tìm hàm X ở đâu?"
3. **Formatting và renaming** - Đổi tên biến, format code
4. **Batch operations đơn giản** - Thêm eslint disable comments, update version numbers
5. **Tiết kiệm budget** - Khi budget API hạn chế

```bash
# Chuyển sang Haiku cho tác vụ đơn giản
> /model haiku

# Hoặc
claude --model claude-haiku-4-5
```

<Callout type="tip" title="Chiến lược sử dụng model hiệu quả">
Một chiến lược phổ biến là bắt đầu phiên làm việc với **Sonnet** cho các tác vụ thông thường, chuyển sang **Opus** khi gặp bài toán phức tạp cần suy luận sâu, và dùng **Haiku** cho các tác vụ nhanh. Lệnh `/model` cho phép chuyển đổi mượt mà trong cùng phiên.
</Callout>

<Callout type="warning" title="Chi phí Extended Thinking">
Khi sử dụng extended thinking, chi phí có thể tăng đáng kể vì thinking tokens cũng được tính phí. Opus với extended thinking cho một tác vụ phức tạp có thể tốn $5-10 hoặc hơn. Hãy cân nhắc chỉ bật extended thinking khi thực sự cần thiết.
</Callout>

## Claude Max - Giải pháp chi phí cố định

Nếu bạn sử dụng Claude Code thường xuyên, gói **Claude Max** có thể là lựa chọn kinh tế hơn:

- **Claude Pro** ($20/tháng): Truy cập Claude qua web/app, giới hạn usage
- **Claude Max 5x** ($100/tháng): 5x usage so với Pro, bao gồm Claude Code
- **Claude Max 20x** ($200/tháng): 20x usage, phù hợp cho heavy users

Với Claude Max, bạn không cần lo về chi phí API theo token, giúp thoải mái sử dụng Opus cho các tác vụ quan trọng mà không ngại chi phí.

## Cấu hình Model mặc định

Bạn có thể thiết lập model mặc định trong settings:

```json
// ~/.claude/settings.json
{
  "model": "claude-sonnet-4-6",
  "preferences": {
    "default_model": "claude-sonnet-4-6",
    "thinking_model": "claude-opus-4-6"
  }
}
```

Hoặc qua biến môi trường:

```bash
# Trong .bashrc hoặc .zshrc
export CLAUDE_MODEL="claude-sonnet-4-6"
```

<Callout type="tip" title="Model cho team">
Trong môi trường team, quản trị viên có thể cấu hình model mặc định và giới hạn model nào được phép sử dụng thông qua Anthropic Console, giúp kiểm soát chi phí hiệu quả.
</Callout>
