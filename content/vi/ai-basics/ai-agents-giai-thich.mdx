# AI Agents giải thích: Từ chatbot đến trợ lý tự động

Nếu chatbot AI thông thường giống như một nhân viên tư vấn chỉ biết trả lời câu hỏi, thì **AI Agent** giống như một nhân viên có thể tự lên kế hoạch, sử dụng công cụ, và hoàn thành công việc một cách tự chủ. Đây là xu hướng lớn nhất trong AI năm 2026.

## AI Agent là gì?

**AI Agent** là một hệ thống AI có khả năng:
- **Nhận** mục tiêu hoặc tác vụ từ người dùng
- **Lập kế hoạch** các bước cần thực hiện
- **Sử dụng công cụ** (tools) để tương tác với thế giới bên ngoài
- **Đánh giá** kết quả và điều chỉnh hành động
- **Lặp lại** cho đến khi hoàn thành mục tiêu

<Callout type="info" title="Chatbot vs Agent">
**Chatbot:** Bạn hỏi → AI trả lời → Kết thúc.
**Agent:** Bạn giao việc → AI lập kế hoạch → AI thực hiện nhiều bước → AI sử dụng công cụ → AI kiểm tra kết quả → AI hoàn thành việc.
</Callout>

## Vòng lặp Agent (Agent Loop)

Trái tim của mọi AI Agent là **vòng lặp hành động** (agent loop):

<Diagram chart="graph TD\n    A[👤 Người dùng giao tác vụ] --> B[🤔 Suy nghĩ\nPhân tích tác vụ\nLập kế hoạch]\n    B --> C{Cần sử dụng\ncông cụ?}\n    C -->|Có| D[🔧 Chọn và gọi Tool\nSearch, Code, API, File...]\n    D --> E[📊 Nhận kết quả từ Tool]\n    E --> F[🤔 Đánh giá kết quả\nĐã đủ chưa?]\n    F -->|Chưa đủ| B\n    C -->|Không| G[💬 Tạo câu trả lời]\n    F -->|Đã đủ| G\n    G --> H[📋 Trả kết quả cho người dùng]\n    \n    style A fill:#e3f2fd\n    style B fill:#fff3e0\n    style D fill:#f3e5f5\n    style F fill:#fff8e1\n    style H fill:#e8f5e9" />

## ReAct Pattern: Reasoning + Acting

**ReAct** (Reasoning and Acting) là pattern phổ biến nhất cho AI Agents. Nó kết hợp khả năng **suy luận** (reasoning) và **hành động** (acting) trong cùng một vòng lặp.

```text
# Ví dụ ReAct: "Tìm thời tiết Hà Nội và đề xuất trang phục"

Thought 1: Tôi cần tìm thông tin thời tiết hiện tại ở Hà Nội.
Action 1: search_weather(location="Hà Nội")
Observation 1: Hà Nội - 28°C, độ ẩm 75%, có mưa rào buổi chiều.

Thought 2: Trời nóng ẩm và có mưa. Tôi cần đề xuất trang phục phù hợp.
Action 2: Không cần tool, tôi có đủ thông tin để trả lời.

Final Answer: Thời tiết Hà Nội hôm nay 28°C, độ ẩm cao 75% và
có thể mưa rào buổi chiều. Gợi ý trang phục:
- Áo phông cotton thoáng mát, màu sáng
- Quần short hoặc quần vải nhẹ
- Mang theo ô/áo mưa gọn nhẹ cho buổi chiều
- Giày chống nước hoặc sandals
```

### Ba thành phần của ReAct:

1. **Thought (Suy nghĩ):** Agent phân tích tình huống và quyết định bước tiếp theo
2. **Action (Hành động):** Agent gọi một tool hoặc thực hiện một hành động
3. **Observation (Quan sát):** Agent nhận kết quả và đánh giá

### Cách Agent chọn tool

Khi nhận một tác vụ, agent sẽ được cung cấp danh sách tools kèm mô tả. LLM sẽ quyết định tool nào phù hợp dựa trên mô tả đó.

```python
# Ví dụ định nghĩa tools cho Claude Agent
tools = [
    {
        "name": "search_web",
        "description": "Tìm kiếm thông tin trên web. Dùng khi cần thông tin mới nhất.",
        "input_schema": {
            "type": "object",
            "properties": {
                "query": {"type": "string", "description": "Từ khóa tìm kiếm"}
            },
            "required": ["query"]
        }
    },
    {
        "name": "run_python",
        "description": "Chạy code Python. Dùng cho tính toán, xử lý dữ liệu, tạo biểu đồ.",
        "input_schema": {
            "type": "object",
            "properties": {
                "code": {"type": "string", "description": "Code Python cần chạy"}
            },
            "required": ["code"]
        }
    },
    {
        "name": "send_email",
        "description": "Gửi email. Chỉ dùng khi người dùng yêu cầu gửi email rõ ràng.",
        "input_schema": {
            "type": "object",
            "properties": {
                "to": {"type": "string"},
                "subject": {"type": "string"},
                "body": {"type": "string"}
            },
            "required": ["to", "subject", "body"]
        }
    }
]
```

<Callout type="tip" title="Thiết kế tool tốt">
Mô tả tool càng rõ ràng, agent càng chọn đúng tool. Hãy ghi rõ: tool làm gì, khi nào nên dùng, khi nào KHÔNG nên dùng, và các tham số cần thiết.
</Callout>

## Multi-Agent Systems

Khi tác vụ quá phức tạp cho một agent, chúng ta có thể sử dụng **hệ thống đa agent** - nhiều agent chuyên biệt phối hợp với nhau.

<Diagram chart="graph TD\n    A[👤 Người dùng\nYêu cầu: Phân tích thị trường\nvà viết báo cáo] --> B[🎯 Orchestrator Agent\nPhân công và điều phối]\n    B --> C[📊 Research Agent\nTìm kiếm và thu thập dữ liệu]\n    B --> D[📈 Analysis Agent\nPhân tích số liệu và xu hướng]\n    B --> E[✍️ Writer Agent\nViết báo cáo từ kết quả phân tích]\n    C --> F[Kết quả nghiên cứu]\n    D --> G[Kết quả phân tích]\n    F --> D\n    G --> E\n    E --> H[📋 Báo cáo hoàn chỉnh]\n    H --> A\n    \n    style B fill:#e3f2fd\n    style C fill:#f3e5f5\n    style D fill:#fff8e1\n    style E fill:#e8f5e9" />

### Các kiến trúc Multi-Agent phổ biến:

**1. Hierarchical (Phân cấp):** Một orchestrator agent phân công cho các agent con. Phù hợp cho workflow có cấu trúc rõ ràng.

**2. Collaborative (Hợp tác):** Các agent ngang hàng trao đổi và hợp tác. Phù hợp cho brainstorming, debate, peer review.

**3. Sequential (Tuần tự):** Output của agent này là input của agent kia, như một pipeline. Phù hợp cho quy trình sản xuất nội dung.

## Ví dụ thực tế: Coding Agent

Một coding agent (như Claude Code, Cursor, hoặc GitHub Copilot Workspace) hoạt động như sau:

```text
Người dùng: "Thêm dark mode cho trang settings"

Agent Thought: Tôi cần:
1. Tìm file settings page hiện tại
2. Xem cấu trúc CSS/styling hiện tại
3. Thêm logic dark mode
4. Test kết quả

Action 1: search_files("settings page component")
Observation: Tìm thấy src/pages/Settings.tsx

Action 2: read_file("src/pages/Settings.tsx")
Observation: [Nội dung file, sử dụng Tailwind CSS]

Action 3: read_file("src/styles/globals.css")
Observation: [Chưa có dark mode config]

Action 4: edit_file("tailwind.config.js", add darkMode: 'class')
Observation: File đã được cập nhật

Action 5: edit_file("src/pages/Settings.tsx", add dark: variants)
Observation: File đã được cập nhật

Action 6: edit_file("src/components/ThemeToggle.tsx", create new)
Observation: Component mới đã được tạo

Action 7: run_command("npm run build")
Observation: Build thành công, không có lỗi

Final: Đã thêm dark mode cho trang Settings với toggle button.
Các file đã thay đổi: [danh sách files]
```

## Thách thức của AI Agents

<Callout type="warning" title="Những rủi ro cần lưu ý">
AI Agents mạnh mẽ nhưng cũng tiềm ẩn rủi ro. Chúng có thể thực hiện hành động không mong muốn, xóa dữ liệu, gọi API tốn phí, hoặc gửi email nhầm. Luôn cần có cơ chế **human-in-the-loop** cho các hành động quan trọng.
</Callout>

### Các thách thức chính:

1. **Reliability (Độ tin cậy):** Agent có thể mắc kẹt trong vòng lặp hoặc đi sai hướng
2. **Cost (Chi phí):** Mỗi bước trong agent loop đều tốn token = tốn tiền
3. **Latency (Độ trễ):** Nhiều bước suy luận = thời gian chờ lâu hơn
4. **Safety (An toàn):** Agent có quyền thực hiện hành động, cần kiểm soát cẩn thận
5. **Debugging:** Khó debug khi agent thực hiện hàng chục bước

### Giải pháp:

- **Guardrails:** Giới hạn actions mà agent có thể thực hiện
- **Human approval:** Yêu cầu xác nhận cho actions quan trọng
- **Token budget:** Giới hạn số token/bước tối đa
- **Logging:** Ghi lại mọi thought và action để review
- **Sandboxing:** Chạy trong môi trường cách ly

## Tương lai của AI Agents

AI Agents đang phát triển nhanh chóng và dự kiến sẽ:

- **Tự động hóa workflow phức tạp** trong doanh nghiệp
- **Cá nhân hóa trải nghiệm** dựa trên context và lịch sử
- **Phối hợp** giữa nhiều agent chuyên biệt
- **Tích hợp sâu** với các hệ thống IT hiện có
- **Hoạt động liên tục** (always-on) thay vì chỉ khi được gọi

<Callout type="tip" title="Bắt đầu với AI Agents">
Nếu bạn muốn thử nghiệm AI Agents, hãy bắt đầu với Claude Code (cho developer), hoặc thử các no-code agent builder như Zapier AI Actions, Make.com AI. Bạn không cần là lập trình viên để tận dụng sức mạnh của AI Agents.
</Callout>

## Tổng kết

AI Agents đại diện cho bước tiến lớn từ "AI trả lời câu hỏi" sang "AI hoàn thành công việc". Những điểm chính:

- Agent = LLM + Tool Use + Agent Loop
- **ReAct pattern** (Think → Act → Observe) là nền tảng
- **Tool use** cho phép agent tương tác với thế giới thực
- **Multi-agent** giải quyết các tác vụ phức tạp
- Cần cân bằng giữa **tự chủ** và **an toàn**

Trong bài viết tiếp theo, chúng ta sẽ tìm hiểu về **RAG (Retrieval-Augmented Generation)** - kỹ thuật giúp AI trả lời chính xác hơn bằng cách kết hợp với nguồn dữ liệu bên ngoài.
