# Docker Cơ Bản - Từ Khái Niệm Đến Container Đầu Tiên

"Ở máy tôi chạy bình thường mà!" — Nếu bạn từng nghe (hoặc nói) câu này, Docker chính là giải pháp. Docker là nền tảng mã nguồn mở cho phép bạn đóng gói ứng dụng cùng toàn bộ môi trường cần thiết vào một đơn vị gọi là **container**, đảm bảo ứng dụng chạy nhất quán trên mọi hệ thống — từ máy dev đến server production.

Bài viết này sẽ đưa bạn từ khái niệm cơ bản đến việc chạy container đầu tiên.

## Container Là Gì?

Container là một đơn vị phần mềm nhẹ, chứa tất cả những gì cần thiết để chạy ứng dụng: mã nguồn, thư viện, công cụ hệ thống và cấu hình. Điểm khác biệt quan trọng nhất so với máy ảo (VM): container **chia sẻ kernel** của hệ điều hành host, nên khởi động trong vài giây và tiêu tốn rất ít tài nguyên.

## Kiến Trúc Docker

Docker hoạt động theo mô hình **client-server** gồm ba thành phần chính:

<Diagram chart="graph LR\n    A[Docker Client\n docker CLI] -->|REST API| B[Docker Daemon\n dockerd]\n    B --> C[Images]\n    B --> D[Containers]\n    B --> E[Networks]\n    B --> F[Volumes]\n    B <-->|pull/push| G[Docker Registry\n Docker Hub]" />

### Docker Daemon (dockerd)

Là tiến trình chạy nền, quản lý tất cả các đối tượng Docker: image, container, network, volume. Daemon lắng nghe yêu cầu từ Docker Client thông qua REST API.

### Docker Client (docker)

Là công cụ dòng lệnh bạn sử dụng hằng ngày. Khi gõ `docker run`, client gửi lệnh đến daemon để thực thi.

### Docker Registry

Kho lưu trữ và phân phối Docker image. **Docker Hub** là registry công khai lớn nhất, chứa hàng triệu image sẵn sàng sử dụng. Bạn cũng có thể dựng registry riêng cho tổ chức.

## Các Khái Niệm Cốt Lõi

<Diagram chart="graph TD\n    A[Dockerfile] -->|docker build| B[Image]\n    B -->|docker run| C[Container]\n    B -->|docker push| D[Registry]\n    D -->|docker pull| B" />

### Image

Image là **bản thiết kế bất biến** (immutable blueprint) của container. Nó được xây dựng từ nhiều layer chồng lên nhau — mỗi lệnh trong Dockerfile tạo ra một layer mới. Khi bạn thay đổi một layer, chỉ layer đó và các layer phía trên cần được rebuild.

### Container

Container là một **instance đang chạy** của image. Bạn có thể tạo nhiều container từ cùng một image, mỗi container hoạt động độc lập với filesystem riêng.

### Dockerfile

File văn bản chứa tập hợp các lệnh để xây dựng image. Đây là "công thức" để Docker biết cách đóng gói ứng dụng của bạn.

### Volume

Cơ chế lưu trữ dữ liệu bền vững (persistent data). Dữ liệu trong container sẽ mất khi container bị xóa, nhưng volume giúp giữ lại dữ liệu quan trọng như database.

## Cài Đặt Docker

### macOS / Windows

Tải và cài đặt **Docker Desktop** — bao gồm Docker Engine, CLI, Compose và giao diện đồ họa.

```bash
# Tải từ: https://www.docker.com/products/docker-desktop/
# Sau khi cài, kiểm tra:
docker --version
# Docker version 29.x.x
```

### Ubuntu / Debian

```bash
# Cài đặt Docker Engine
sudo apt-get update
sudo apt-get install docker-ce docker-ce-cli containerd.io docker-compose-plugin

# Cho phép user hiện tại chạy Docker không cần sudo
sudo usermod -aG docker $USER
# Đăng xuất rồi đăng nhập lại để có hiệu lực

# Kiểm tra cài đặt
docker --version
docker run hello-world
```

<Callout type="tip">Lệnh `docker run hello-world` sẽ tải image `hello-world` từ Docker Hub và chạy nó. Nếu thấy thông báo chào mừng, Docker đã hoạt động.</Callout>

## Hands-on: Container Đầu Tiên

Hãy chạy một web server Nginx trong container:

```bash
# Bước 1: Tải image nginx từ Docker Hub
docker pull nginx

# Bước 2: Chạy container
docker run -d --name webserver -p 8080:80 nginx
```

Mở trình duyệt tại `http://localhost:8080` — bạn sẽ thấy trang chào mừng của Nginx.

### Giải Thích Lệnh docker run

```bash
docker run -d --name webserver -p 8080:80 -v ./html:/usr/share/nginx/html nginx
#          │   │                │           │                                 │
#          │   │                │           │                                 └─ Image
#          │   │                │           └─ Mount thư mục local vào container
#          │   │                └─ Map port: host 8080 → container 80
#          │   └─ Đặt tên container
#          └─ Chạy nền (detached mode)
```

### Các Lệnh Quản Lý Container

```bash
# Xem container đang chạy
docker ps

# Xem tất cả container (bao gồm đã dừng)
docker ps -a

# Xem log
docker logs webserver

# Truy cập vào bên trong container
docker exec -it webserver bash

# Dừng container
docker stop webserver

# Khởi động lại
docker start webserver

# Xóa container (phải dừng trước)
docker stop webserver && docker rm webserver
```

### Quản Lý Image

```bash
# Liệt kê image đã tải
docker images

# Tải image cụ thể
docker pull node:22-alpine

# Xóa image
docker rmi nginx
```

## Viết Dockerfile Đầu Tiên

Hãy đóng gói một ứng dụng Node.js đơn giản:

```dockerfile
# Base image — Alpine Linux giúp image nhẹ (~50MB thay vì ~300MB)
FROM node:22-alpine

# Thư mục làm việc trong container
WORKDIR /app

# Copy file package trước để tận dụng Docker layer cache
# Nếu dependencies không đổi, layer này được cache → build nhanh hơn
COPY package*.json ./
RUN npm ci --omit=dev

# Copy mã nguồn (sau dependencies để tận dụng cache)
COPY . .

# Khai báo port ứng dụng lắng nghe
EXPOSE 3000

# Tạo user không phải root — bảo mật cơ bản
RUN addgroup -S appgroup && adduser -S appuser -G appgroup
USER appuser

# Lệnh chạy khi container khởi động
CMD ["node", "server.js"]
```

<Callout type="warning">Luôn tạo file `.dockerignore` để tránh đưa file không cần thiết vào image. Điều này giúp image nhỏ hơn, build nhanh hơn, và bảo mật hơn.</Callout>

```text
# .dockerignore
node_modules
.git
.env
*.md
Dockerfile
```

### Build và Chạy

```bash
# Build image với tag my-app phiên bản 1.0
docker build -t my-app:1.0 .

# Chạy container từ image vừa build
docker run -d --name my-app -p 3000:3000 my-app:1.0

# Kiểm tra ứng dụng
curl http://localhost:3000
```

## Docker Compose — Chạy Nhiều Container

Ứng dụng thực tế thường cần nhiều thành phần: web server, database, cache. **Docker Compose** cho phép bạn định nghĩa và quản lý tất cả trong một file `compose.yaml`.

<Callout type="info">Docker Compose v5 (phiên bản hiện tại) không cần trường `version` trong file compose nữa. Tên file khuyến nghị là `compose.yaml` thay vì `docker-compose.yml`.</Callout>

### Ví Dụ: Ứng Dụng Web + PostgreSQL + Redis

```yaml
# compose.yaml
services:
  # Ứng dụng web
  web:
    build: .
    ports:
      - "3000:3000"
    environment:
      - DATABASE_URL=postgres://user:password@db:5432/myapp
      - REDIS_URL=redis://cache:6379
    depends_on:
      db:
        condition: service_healthy
      cache:
        condition: service_started
    restart: unless-stopped

  # PostgreSQL
  db:
    image: postgres:17-alpine
    environment:
      POSTGRES_USER: user
      POSTGRES_PASSWORD: password
      POSTGRES_DB: myapp
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U user -d myapp"]
      interval: 5s
      timeout: 5s
      retries: 5

  # Redis
  cache:
    image: redis:7-alpine
    volumes:
      - redis_data:/data

volumes:
  postgres_data:
  redis_data:
```

### Các Lệnh Compose Thường Dùng

```bash
# Khởi động tất cả services (build nếu cần)
docker compose up -d

# Xem trạng thái
docker compose ps

# Xem log realtime
docker compose logs -f

# Log của một service cụ thể
docker compose logs -f web

# Dừng tất cả
docker compose down

# Dừng và xóa cả volume (⚠️ mất dữ liệu!)
docker compose down -v

# Rebuild khi thay đổi code
docker compose up -d --build
```

## Kết Luận

Bạn đã nắm được những kiến thức nền tảng về Docker:

- **Container** là gì và khác VM như thế nào
- **Kiến trúc** client-server của Docker
- Cách **cài đặt** và **chạy container** đầu tiên
- Viết **Dockerfile** để đóng gói ứng dụng
- Dùng **Docker Compose** để quản lý nhiều container

Bước tiếp theo: hãy Docker hóa một dự án thực tế của bạn. Trong bài tiếp theo của series, chúng ta sẽ đi sâu hơn vào Docker Compose với các ứng dụng multi-container phức tạp hơn.
