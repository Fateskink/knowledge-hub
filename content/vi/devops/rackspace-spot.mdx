# Rackspace Spot: Hạ Tầng Cloud Giá Rẻ Với Kubernetes Managed

## 1. Rackspace Spot Là Gì?

Trong bối cảnh chi phí cloud infrastructure ngày càng trở thành gánh nặng cho các startup và doanh nghiệp vừa và nhỏ, **Rackspace Spot** xuất hiện như một giải pháp đột phá. Ra mắt vào tháng 3/2024, Rackspace Spot là sản phẩm đồng phát triển bởi **Rackspace Technology** và **Platform9** - hai tên tuổi lớn trong lĩnh vực cloud và Kubernetes.

Ý tưởng cốt lõi của Rackspace Spot là xây dựng một **"open market auction for cloud servers"** - thị trường đấu giá mở cho máy chủ cloud. Thay vì nhà cung cấp áp đặt mức giá cố định, cung và cầu trên thị trường sẽ quyết định giá compute. Toàn bộ hạ tầng được giao cho người dùng dưới dạng **fully managed Kubernetes clusters**, nghĩa là bạn không cần lo quản lý control plane, networking hay storage - tất cả đã được xử lý sẵn.

<Callout type="info" title="Phản hồi từ người dùng thực">
"Khi tìm thấy Rackspace Spot, tưởng như quá tốt để là thật. Nhưng sau 6 tháng sử dụng, chi phí infrastructure của chúng tôi giảm hơn 85% so với AWS EKS." - CTO SmartHub.ai

Điểm khác biệt lớn nhất so với AWS, GCP hay Azure là **mô hình định giá**. Trong khi các hyperscaler tính giá theo bảng giá cố định (hoặc reserved instances phải cam kết dài hạn), Rackspace Spot cho phép bạn đặt giá mong muốn và hệ thống sẽ tự động khớp lệnh dựa trên capacity sẵn có.

## 2. Cơ Chế Đấu Giá (Auction) Hoạt Động Thế Nào?

Trái tim của Rackspace Spot là **Auction Engine** - hệ thống đấu giá liên tục chạy để kết nối capacity sẵn có với nhu cầu của người dùng.

<Diagram chart="graph LR\n    A[Người dùng đặt Bid] --> B[Auction Engine]\n    B --> C{Capacity sẵn có?}\n    C -->|Có| D[Khớp lệnh thành công]\n    C -->|Không| E[Chờ capacity]\n    D --> F[Provision K8s Cluster]\n    F --> G[Workloads chạy]\n    E -->|Capacity xuất hiện| D" />

**Quy trình hoạt động chi tiết:**

1. **Đặt bid**: Người dùng chọn loại server (flavor) và đặt mức giá mong muốn, bắt đầu từ chỉ **$0.001/giờ**.
2. **Realtime pricing**: Dashboard hiển thị giá thị trường theo thời gian thực và mức capacity sẵn có tại các mức giá khác nhau, giúp bạn đưa ra quyết định chính xác.
3. **Khớp lệnh**: Auction Engine tính toán giá compute dựa trên bid thấp nhất có thể được fulfill bởi capacity hiện tại.
4. **Provision**: Khi khớp lệnh thành công, Kubernetes cluster được tự động provision và sẵn sàng sử dụng.

Rackspace Spot cung cấp hai loại server:

- **Spot Servers**: Giá rẻ nhất, nhưng có thể bị **recycle** (thu hồi) bất kỳ lúc nào khi capacity cần được phân bổ lại. Khi bị recycle, stateful workloads sẽ tự động migrate sang server khác.
- **On-demand Servers**: Đảm bảo uptime liên tục (guaranteed uptime), nhưng giá cao hơn spot servers. Phù hợp cho production workloads quan trọng.

<Callout type="warning" title="Lưu ý về Spot Servers">
Spot server có thể bị recycle bất kỳ lúc nào khi demand tăng cao. Hãy thiết kế ứng dụng theo kiến trúc stateless hoặc sử dụng persistent storage để dữ liệu không bị mất khi server bị thu hồi.
</Callout>

## 5. Kiến Trúc và Tính Năng

<Diagram chart="graph TB\n    A[Người dùng] --> B[Dashboard / spotctl CLI / Terraform]\n    B --> C[Rackspace Spot API]\n    C --> D[Auction Engine]\n    D --> E[Managed Control Plane]\n    E --> F[K8s Cluster]\n    F --> G[Worker Nodes - Spot]\n    F --> H[Worker Nodes - On-demand]\n    F --> I[Persistent Volumes SSD/SATA]\n    F --> J[Load Balancers]\n    G --> K[Ứng dụng của bạn]\n    H --> K\n    E -->|Cluster-API| F\n    F -->|Calico CNI| L[Network Policies]" />

**Các tính năng chính:**

- **Managed Control Plane**: Dựa trên Cluster-API, hoàn toàn do Rackspace quản lý. Bạn không cần lo bảo trì etcd, API server hay scheduler.
- **Auto-scaling Node Pools**: Tự động tăng/giảm số lượng nodes dựa trên workload demand.
- **Calico CNI**: Hỗ trợ network policies đầy đủ, cho phép kiểm soát traffic giữa các pods.
- **2 Storage Classes**: SSD persistent volumes cho hiệu năng cao và SATA persistent volumes cho lưu trữ dung lượng lớn.
- **Load Balancers tích hợp**: Expose services ra bên ngoài dễ dàng.
- **Stateful Workload Support**: Khi spot server bị recycle, persistent storage tự động migrate sang server mới, đảm bảo dữ liệu không bị mất.

**SLA cam kết:**
- **99.9%** Kubernetes API uptime
- **>99%** Node Delivery Rate (tỷ lệ provision node thành công)

## 6. Cách Deploy - 3 Phương Pháp

### A. Web Dashboard

Cách đơn giản nhất để bắt đầu:

1. Đăng ký tài khoản tại **spot.rackspace.com**
2. Tạo **Cloudspace** (tương đương một K8s cluster)
3. Chọn compute flavor, số lượng nodes, và đặt bid price
4. Deploy ứng dụng trực tiếp qua giao diện UI

### B. spotctl CLI

Dành cho những ai yêu thích dòng lệnh:

```bash
# Cài đặt spotctl
curl -sL https://spot.rackspace.com/install | bash

# Đăng nhập
spotctl auth login

# Tạo cloudspace mới
spotctl cloudspace create --name my-project \
  --bid-price 0.01 --server-class gp.vs1.small-sjc

# Lấy kubeconfig để kết nối kubectl
spotctl cloudspace kubeconfig --name my-project > kubeconfig.yaml
export KUBECONFIG=kubeconfig.yaml

# Deploy ứng dụng bằng kubectl như bình thường
kubectl apply -f deployment.yaml
```

### C. Terraform Provider

Phù hợp cho Infrastructure as Code workflows:

```hcl
terraform {
  required_providers {
    spot = {
      source = "rackerlabs/spot"
    }
  }
}

provider "spot" {
  token = var.spot_token  # Lấy từ Dashboard → API Access
}

resource "spot_cloudspace" "my_project" {
  cloudspace_name = "my-project"
  region          = "us-central-dfw-1"

  instance {
    server_class = "gp.vs1.small"
    bid_price    = 0.01
  }
}
```

## 7. Ví Dụ Thực Tế: Deploy Next.js App

Sau khi có Kubernetes cluster từ Rackspace Spot, việc deploy ứng dụng hoàn toàn giống với bất kỳ K8s cluster nào khác. Dưới đây là ví dụ deploy một ứng dụng Next.js:

```yaml
# deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nextjs-app
spec:
  replicas: 2
  selector:
    matchLabels:
      app: nextjs
  template:
    metadata:
      labels:
        app: nextjs
    spec:
      containers:
      - name: nextjs
        image: your-registry/nextjs-app:latest
        ports:
        - containerPort: 3000
        resources:
          requests:
            memory: "256Mi"
            cpu: "250m"
---
apiVersion: v1
kind: Service
metadata:
  name: nextjs-service
spec:
  type: LoadBalancer
  ports:
  - port: 80
    targetPort: 3000
  selector:
    app: nextjs
```

Sau khi apply, Rackspace Spot sẽ tự động provision một Load Balancer và cung cấp external IP để truy cập ứng dụng. Với 2 replicas chạy trên spot servers, chi phí có thể chỉ vài dollar mỗi tháng.

## 8. Khi Nào Nên Dùng Rackspace Spot?

Rackspace Spot phù hợp nhất cho các trường hợp sau:

- **Dự án nhỏ và trung bình** cần Kubernetes managed với chi phí tối thiểu
- **Staging và dev environments** - không cần guaranteed uptime, tiết kiệm tối đa
- **Batch processing và CI/CD runners** - workloads chạy theo lô, không cần server chạy liên tục
- **AI/ML training** - tận dụng GPU instances (H100, A30) với giá đấu giá rẻ hơn nhiều so với on-demand pricing của AWS/GCP

<Callout type="tip" title="Chiến lược kết hợp Spot + On-demand">
Để tối ưu chi phí mà vẫn đảm bảo độ tin cậy, hãy kết hợp cả hai loại nodes: đặt các workloads quan trọng (database, payment service) trên **on-demand nodes** để đảm bảo uptime, còn các workloads có khả năng chịu lỗi (web frontends, workers, batch jobs) chạy trên **spot nodes** để tiết kiệm chi phí.
</Callout>

## 9. Hạn Chế Cần Biết

Dù có nhiều ưu điểm, Rackspace Spot cũng có những hạn chế bạn cần cân nhắc trước khi quyết định sử dụng:

- **Spot servers có thể bị recycle bất kỳ lúc nào**: Tương tự AWS Spot Instances, server có thể bị thu hồi khi demand tăng. Ứng dụng cần được thiết kế để chịu được việc node bị mất đột ngột.
- **Ít regions hơn AWS/GCP**: Hiện tại Rackspace Spot chỉ có mặt tại một số data centers, chủ yếu ở Mỹ. Nếu bạn cần deploy gần người dùng ở châu Á hay châu Âu, đây có thể là trở ngại.
- **Hệ sinh thái dịch vụ managed hạn chế**: Không có managed database (như RDS), serverless functions (như Lambda), hay message queue (như SQS). Bạn cần tự deploy các thành phần này trên Kubernetes hoặc sử dụng dịch vụ bên thứ ba.
- **Documentation còn mới và community nhỏ**: So với AWS hay GCP, tài liệu hướng dẫn và cộng đồng người dùng vẫn đang trong giai đoạn phát triển.
- **Cần kiến thức Kubernetes cơ bản**: Vì mọi thứ chạy trên K8s, bạn cần hiểu các khái niệm như Deployments, Services, PersistentVolumeClaims để vận hành hiệu quả.
