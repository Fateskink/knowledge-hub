# MQTT - Giao thức IoT

MQTT (Message Queuing Telemetry Transport) là một giao thức nhắn tin nhẹ (lightweight messaging protocol), được thiết kế cho các thiết bị có tài nguyên hạn chế và mạng có băng thông thấp, độ trễ cao. Đây là giao thức phổ biến nhất trong thế giới IoT (Internet of Things), từ cảm biến nhiệt độ đến hệ thống smart home phức tạp.

## MQTT là gì?

MQTT là một giao thức truyền tin dựa trên mô hình **publish/subscribe** (xuất bản/đăng ký). Thay vì các client giao tiếp trực tiếp với nhau (như HTTP), tất cả giao tiếp đi qua một trung gian gọi là **broker**. Client có thể publish (gửi) message đến một topic, và các client khác subscribe (đăng ký) topic đó để nhận message.

<Callout type="info">MQTT được phát minh bởi Andy Stanford-Clark (IBM) và Arlen Nipper vào năm 1999, ban đầu để giám sát đường ống dẫn dầu qua vệ tinh. Phiên bản hiện tại là MQTT 5.0, được chuẩn hóa bởi OASIS.</Callout>

### Đặc điểm chính của MQTT

- **Nhẹ**: Header tối thiểu chỉ 2 bytes
- **Bi-directional**: Giao tiếp hai chiều giữa client và broker
- **Publish/Subscribe**: Tách biệt người gửi và người nhận
- **QoS levels**: 3 mức đảm bảo chất lượng truyền tin
- **Retained messages**: Lưu trữ message cuối cùng của topic
- **Last Will & Testament**: Thông báo khi client mất kết nối
- **Session persistence**: Duy trì phiên kết nối

### Cách hoạt động

1. **Publisher** gửi message đến một **topic** trên broker
2. **Broker** nhận message và chuyển tiếp đến tất cả **subscriber** của topic đó
3. **Subscriber** nhận message mà không cần biết publisher là ai

### Topic Structure

Topic trong MQTT có cấu trúc dạng phân cấp, phân cách bởi dấu `/`:

```
home/living-room/temperature
home/living-room/humidity
home/bedroom/temperature
office/server-room/temperature
```

**Wildcard patterns:**
- `+` : Thay thế một cấp (single level) - `home/+/temperature` match `home/living-room/temperature` và `home/bedroom/temperature`
- `#` : Thay thế nhiều cấp (multi level) - `home/#` match tất cả topic bắt đầu bằng `home/`

<Callout type="warning">Tránh subscribe topic `#` (tất cả topic) trong production vì nó sẽ nhận tất cả message đi qua broker, gây quá tải cho client.</Callout>

## Retained Messages và Last Will

### Retained Messages

Khi publish message với cờ `retain=True`, broker sẽ lưu trữ message cuối cùng của topic. Bất kỳ client nào subscribe topic đó sau này sẽ ngay lập tức nhận được message lưu trữ, không cần chờ đợi publisher gửi lại.

### Last Will & Testament (LWT)

Client có thể cấu hình một "di chúc" khi kết nối. Nếu client mất kết nối đột ngột (không gửi DISCONNECT), broker sẽ tự động publish message LWT, giúp các client khác biết rằng thiết bị đã offline.

### Publisher - Gửi dữ liệu cảm biến

```python
import paho.mqtt.client as mqtt
import json
import time
import random

# Cấu hình kết nối
BROKER_HOST = "localhost"
BROKER_PORT = 1883
CLIENT_ID = "sensor-living-room-01"

def on_connect(client, userdata, flags, rc):
    if rc == 0:
        print("Kết nối thành công với MQTT Broker!")
    else:
        print(f"Kết nối thất bại, mã lỗi: {rc}")

def on_publish(client, userdata, mid):
    print(f"Message {mid} đã được publish thành công")

# Tạo client và cấu hình
client = mqtt.Client(client_id=CLIENT_ID)
client.on_connect = on_connect
client.on_publish = on_publish

# Cấu hình Last Will & Testament
client.will_set(
    topic="home/living-room/status",
    payload=json.dumps({"status": "offline", "device": CLIENT_ID}),
    qos=1,
    retain=True
)

# Xác thực (nếu broker yêu cầu)
client.username_pw_set("mqtt_user", "mqtt_password")

# Kết nối
client.connect(BROKER_HOST, BROKER_PORT, keepalive=60)
client.loop_start()

# Gửi dữ liệu cảm biến liên tục
try:
    while True:
        # Mô phỏng dữ liệu cảm biến
        temperature = round(random.uniform(20, 35), 1)
        humidity = round(random.uniform(40, 80), 1)

        # Publish nhiệt độ (QoS 0 - dữ liệu cảm biến)
        temp_payload = json.dumps({
            "value": temperature,
            "unit": "celsius",
            "device": CLIENT_ID,
            "timestamp": time.time()
        })
        client.publish(
            topic="home/living-room/temperature",
            payload=temp_payload,
            qos=0,
            retain=True
        )

        # Publish độ ẩm (QoS 1 - quan trọng hơn)
        humidity_payload = json.dumps({
            "value": humidity,
            "unit": "percent",
            "device": CLIENT_ID,
            "timestamp": time.time()
        })
        client.publish(
            topic="home/living-room/humidity",
            payload=humidity_payload,
            qos=1,
            retain=True
        )

        print(f"Sent: temp={temperature}C, humidity={humidity}%")
        time.sleep(5)  # Gửi mỗi 5 giây

except KeyboardInterrupt:
    print("Dừng gửi dữ liệu")
    # Gửi trạng thái offline
    client.publish(
        "home/living-room/status",
        json.dumps({"status": "offline", "device": CLIENT_ID}),
        qos=1, retain=True
    )
    client.loop_stop()
    client.disconnect()
```

### Subscriber - Nhận và xử lý dữ liệu

```python
import paho.mqtt.client as mqtt
import json

BROKER_HOST = "localhost"
BROKER_PORT = 1883

def on_connect(client, userdata, flags, rc):
    print("Đã kết nối, đang subscribe các topic...")
    # Subscribe tất cả topic trong nhà
    client.subscribe("home/#", qos=1)

def on_message(client, userdata, msg):
    topic = msg.topic
    try:
        payload = json.loads(msg.payload.decode())
    except json.JSONDecodeError:
        payload = msg.payload.decode()

    print(f"Topic: {topic}")
    print(f"Payload: {payload}")
    print(f"QoS: {msg.qos}, Retain: {msg.retain}")
    print("---")

    # Xử lý cảnh báo nhiệt độ cao
    if "temperature" in topic:
        temp = payload.get("value", 0)
        if temp > 30:
            print(f"CẢNH BÁO: Nhiệt độ cao {temp}C tại {topic}!")
            client.publish(
                "home/alerts",
                json.dumps({
                    "type": "high_temperature",
                    "value": temp,
                    "source": topic
                }),
                qos=2  # Đảm bảo cảnh báo được gửi chính xác
            )

# Tạo và cấu hình client
client = mqtt.Client(client_id="dashboard-app")
client.on_connect = on_connect
client.on_message = on_message
client.username_pw_set("mqtt_user", "mqtt_password")

client.connect(BROKER_HOST, BROKER_PORT, keepalive=60)
client.loop_forever()  # Chạy liên tục
```

- Đo độ ẩm đất, nhiệt độ không khí

- Giám sát sức khỏe cây trồng

## Bảo mật MQTT

```python
# Kết nối MQTT với TLS/SSL
client = mqtt.Client(client_id="secure-client")

# Cấu hình TLS
client.tls_set(
    ca_certs="/path/to/ca.crt",
    certfile="/path/to/client.crt",
    keyfile="/path/to/client.key"
)

# Kết nối qua port TLS (8883)
client.connect("broker.example.com", 8883, keepalive=60)
```

<Callout type="danger">Không bao giờ sử dụng MQTT không mã hóa (port 1883) trên mạng công khai. Luôn sử dụng TLS (port 8883) và xác thực username/password hoặc certificate trong production.</Callout>

## Kết luận

MQTT là giao thức lý tưởng cho các ứng dụng IoT nhờ sự đơn giản, hiệu quả và độ tin cậy. Với mô hình publish/subscribe, nhiều mức QoS và khả năng hoạt động trên mạng không ổn định, MQTT đã trở thành xu hướng cốt lõi của IoT. Dù bạn đang xây dựng hệ thống smart home hay giám sát công nghiệp, MQTT đều là lựa chọn hàng đầu.
