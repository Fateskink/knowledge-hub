# Message Queue - RabbitMQ và Kafka

Trong kiến trúc microservices và hệ thống phân tán, các service cần giao tiếp với nhau một cách đáng tin cậy và không đồng bộ. Message Queue là giải pháp cho vấn đề này -- nó đóng vai trò trung gian, nhận và phân phối tin nhắn giữa các thành phần trong hệ thống.

## Message Queue là gì?

Message Queue (hàng đợi tin nhắn) là một cơ chế giao tiếp không đồng bộ giữa các thành phần phần mềm. Thay vì gọi trực tiếp (synchronous call), service A gửi tin nhắn vào queue và service B xử lý khi sẵn sàng.

<Diagram chart="graph LR\n    A[Producer\nService A] -->|Gửi tin nhắn| B[Message Queue]\n    B -->|Lấy tin nhắn| C[Consumer\nService B]\n    B -->|Lấy tin nhắn| D[Consumer\nService C]" />

### Tại sao cần Message Queue?

1. **Tách rời các service (Decoupling)**: Producer không cần biết Consumer là ai
2. **Cân bằng tải (Load Leveling)**: Queue hoạt động như buffer khi lượng request tăng đột ngột
3. **Độ tin cậy (Reliability)**: Tin nhắn không bị mất ngay cả khi Consumer tạm ngừng
4. **Mở rộng dễ dàng (Scalability)**: Thêm Consumer để xử lý song song

<Callout type="info">Hãy tưởng tượng một nhà hàng: khách hàng (Producer) đặt món, phiếu order được dán lên bảng (Queue), và đầu bếp (Consumer) lấy phiếu để nấu theo thứ tự. Khách hàng không cần đợi trước bếp, và nhà hàng có thể thêm nhiều đầu bếp khi đông khách.</Callout>

## Các mô hình giao tiếp

### Point-to-Point (Queue)

Mỗi tin nhắn chỉ được xử lý bởi một Consumer duy nhất. Khi có nhiều Consumer, tin nhắn được phân phối (round-robin).

<Diagram chart="graph LR\n    A[Producer] --> B[Queue]\n    B --> C[Consumer 1]\n    B --> D[Consumer 2]\n    B --> E[Consumer 3]" />

### Publish/Subscribe (Pub/Sub)

Một tin nhắn được gửi đến nhiều Consumer cùng lúc thông qua topic hoặc exchange.

<Diagram chart="graph LR\n    A[Publisher] --> B[Topic/Exchange]\n    B --> C[Subscriber 1]\n    B --> D[Subscriber 2]\n    B --> E[Subscriber 3]" />

## RabbitMQ

RabbitMQ là message broker phổ biến nhất, hỗ trợ nhiều giao thức (AMQP, MQTT, STOMP) và nhiều mô hình giao tiếp.

### Kiến trúc RabbitMQ

<Diagram chart="graph LR\n    A[Producer] -->|Publish| B[Exchange]\n    B -->|Routing| C[Queue 1]\n    B -->|Routing| D[Queue 2]\n    C -->|Consume| E[Consumer A]\n    D -->|Consume| F[Consumer B]" />

### Ví dụ RabbitMQ với Node.js

```javascript
// === Producer ===
const amqp = require('amqplib');

async function sendMessage() {
  const connection = await amqp.connect('amqp://localhost');
  const channel = await connection.createChannel();

  const queue = 'order-processing';
  await channel.assertQueue(queue, { durable: true });

  const order = {
    orderId: 'ORD-001',
    userId: 'user-123',
    items: [
      { productId: 'P1', quantity: 2, price: 29.99 },
      { productId: 'P2', quantity: 1, price: 49.99 }
    ],
    createdAt: new Date().toISOString()
  };

  channel.sendToQueue(queue, Buffer.from(JSON.stringify(order)), {
    persistent: true  // Tin nhắn không bị mất khi restart
  });

  console.log('Đã gửi order:', order.orderId);
  await channel.close();
  await connection.close();
}
```

```javascript
// === Consumer ===
const amqp = require('amqplib');

async function processOrders() {
  const connection = await amqp.connect('amqp://localhost');
  const channel = await connection.createChannel();

  const queue = 'order-processing';
  await channel.assertQueue(queue, { durable: true });

  // Chỉ xử lý 1 tin nhắn một lúc (fair dispatch)
  channel.prefetch(1);

  console.log('Đang đợi order...');
  channel.consume(queue, async (msg) => {
    const order = JSON.parse(msg.content.toString());
    console.log('Xử lý order:', order.orderId);

    try {
      // Xử lý order (lưu database, gửi email, etc.)
      await processOrder(order);

      // Xác nhận đã xử lý thành công
      channel.ack(msg);
      console.log('Order xử lý xong:', order.orderId);
    } catch (error) {
      // Từ chối và đưa lại queue để thử lại
      channel.nack(msg, false, true);
      console.error('Lỗi xử lý order:', error);
    }
  });
}

processOrders();
```

<Callout type="tip">Luôn sử dụng `persistent: true` cho tin nhắn và `durable: true` cho queue trong môi trường production. Điều này đảm bảo tin nhắn và queue không bị mất khi RabbitMQ restart.</Callout>

## Apache Kafka

Kafka là nền tảng event streaming phân tán, thiết kế cho xử lý dữ liệu lớn với throughput cao. Kafka không chỉ là message queue -- nó là một nền tảng lưu trữ và xử lý event.

### Kiến trúc Kafka

<Diagram chart="graph TD\n    A[Producer] --> B[Kafka Cluster]\n    subgraph Kafka Cluster\n    B --> C[Topic: orders]\n    C --> D[Partition 0]\n    C --> E[Partition 1]\n    C --> F[Partition 2]\n    end\n    D --> G[Consumer Group A]\n    E --> G\n    F --> G\n    D --> H[Consumer Group B]\n    E --> H\n    F --> H" />

### Ví dụ Kafka với Node.js

```javascript
// === Producer ===
const { Kafka } = require('kafkajs');

const kafka = new Kafka({
  clientId: 'order-service',
  brokers: ['localhost:9092']
});

const producer = kafka.producer();

async function sendEvent() {
  await producer.connect();

  await producer.send({
    topic: 'order-events',
    messages: [
      {
        key: 'order-001',
        value: JSON.stringify({
          eventType: 'ORDER_CREATED',
          orderId: 'order-001',
          userId: 'user-123',
          total: 109.97,
          timestamp: Date.now()
        }),
        headers: {
          'event-type': 'ORDER_CREATED'
        }
      }
    ]
  });

  console.log('Event đã được gửi');
  await producer.disconnect();
}
```

```javascript
// === Consumer ===
const consumer = kafka.consumer({ groupId: 'payment-service' });

async function startConsumer() {
  await consumer.connect();
  await consumer.subscribe({
    topic: 'order-events',
    fromBeginning: false
  });

  await consumer.run({
    eachMessage: async ({ topic, partition, message }) => {
      const event = JSON.parse(message.value.toString());
      console.log(`[Partition ${partition}] Event: ${event.eventType}`);

      switch (event.eventType) {
        case 'ORDER_CREATED':
          await processPayment(event);
          break;
        case 'ORDER_CANCELLED':
          await refundPayment(event);
          break;
      }
    }
  });
}

startConsumer();
```

## MQTT

MQTT (Message Queuing Telemetry Transport) là giao thức nhẹ, thiết kế cho IoT và các thiết bị có tài nguyên hạn chế.

```javascript
// MQTT với Node.js
const mqtt = require('mqtt');

const client = mqtt.connect('mqtt://broker.example.com');

// Subscribe vào topic
client.on('connect', () => {
  client.subscribe('sensors/temperature/#', (err) => {
    if (!err) console.log('Đã subscribe');
  });
});

// Nhận tin nhắn
client.on('message', (topic, message) => {
  const data = JSON.parse(message.toString());
  console.log(`${topic}: ${data.value}°C`);
});

// Publish dữ liệu cảm biến
client.publish('sensors/temperature/room-1', JSON.stringify({
  value: 25.5,
  unit: 'celsius',
  timestamp: Date.now()
}));
```

## Event-Driven Architecture

Message Queue là nền tảng của kiến trúc event-driven, nơi các service giao tiếp thông qua event thay vì gọi trực tiếp:

<Diagram chart="graph LR\n    A[Order Service] -->|OrderCreated| B[Event Bus\nKafka/RabbitMQ]\n    B --> C[Payment Service]\n    B --> D[Inventory Service]\n    B --> E[Notification Service]\n    B --> F[Analytics Service]\n    C -->|PaymentProcessed| B\n    D -->|StockUpdated| B" />

<Callout type="warning">Event-driven architecture tăng tính phức tạp của hệ thống. Cần cân nhắc kỹ trước khi áp dụng: quản lý thứ tự event, xử lý lỗi và retry, đảm bảo tính nhất quán cuối cùng (eventual consistency). Bắt đầu với kiến trúc đơn giản và chuyển sang event-driven khi thực sự cần thiết.</Callout>

## Kết luận

Message Queue là thành phần thiết yếu trong kiến trúc microservices hiện đại. RabbitMQ phù hợp cho task queue và routing phức tạp, Kafka cho xử lý dữ liệu lớn và event streaming, MQTT cho IoT. Hãy chọn công cụ phù hợp với yêu cầu cụ thể của dự án.
