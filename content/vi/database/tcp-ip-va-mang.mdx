# TCP/IP và Mạng máy tính

Mỗi khi bạn truy cập một trang web, gửi email hay xem video trực tuyến, dữ liệu của bạn đi qua hàng loạt tầng giao thức mạng. TCP/IP là bộ giao thức nền tảng của Internet, giúp các máy tính giao tiếp với nhau một cách đáng tin cậy.

## Mô hình TCP/IP

Mô hình TCP/IP gồm 4 tầng (layer), mỗi tầng đảm nhiệm một chức năng riêng:

<Diagram chart="graph TD\n    subgraph Mô hình TCP/IP\n    A[Tầng Ứng dụng - Application Layer\nHTTP, HTTPS, FTP, DNS, SMTP] --> B[Tầng Vận chuyển - Transport Layer\nTCP, UDP]\n    B --> C[Tầng Mạng - Internet Layer\nIP, ICMP, ARP]\n    C --> D[Tầng Truy cập Mạng - Network Access Layer\nEthernet, Wi-Fi, Fiber]\n    end" />

### Tầng 1: Network Access Layer (Tầng Truy cập Mạng)

Tầng thấp nhất xử lý việc truyền dữ liệu vật lý qua môi trường mạng (cáp mạng, Wi-Fi, cáp quang). Nó bao gồm các giao thức như Ethernet, Wi-Fi (802.11), và các driver phần cứng.

### Tầng 2: Internet Layer (Tầng Mạng)

Tầng này chịu trách nhiệm định tuyến (routing) -- xác định đường đi của dữ liệu từ nguồn đến đích qua nhiều mạng khác nhau.

- **IP (Internet Protocol)**: Gán địa chỉ cho mỗi thiết bị và định tuyến gói tin
- **ICMP**: Sử dụng cho chẩn đoán mạng (ping, traceroute)
- **ARP**: Ánh xạ địa chỉ IP sang địa chỉ MAC vật lý

```bash
# Xem địa chỉ IP của máy
ip addr show        # Linux
ifconfig            # macOS
ipconfig            # Windows

# Kiểm tra kết nối mạng
ping google.com

# Theo dõi đường đi của gói tin
traceroute google.com    # Linux/macOS
tracert google.com       # Windows
```

### Tầng 3: Transport Layer (Tầng Vận chuyển)

Tầng này đảm bảo dữ liệu được truyền đáng tin cậy (TCP) hoặc nhanh chóng (UDP) giữa hai ứng dụng.

### Tầng 4: Application Layer (Tầng Ứng dụng)

Tầng cao nhất cung cấp giao thức cho các ứng dụng sử dụng: HTTP cho web, SMTP cho email, FTP cho truyền file, DNS cho phân giải tên miền.

## TCP vs UDP

TCP (Transmission Control Protocol) và UDP (User Datagram Protocol) là hai giao thức vận chuyển chính.

### TCP -- Đáng tin cậy

TCP đảm bảo dữ liệu được truyền đầy đủ, đúng thứ tự. Trước khi gửi dữ liệu, TCP thiết lập kết nối qua quá trình 3-way handshake:

<Diagram chart="graph LR\n    A[Client] -->|1. SYN| B[Server]\n    B -->|2. SYN-ACK| A\n    A -->|3. ACK| B\n    A <-->|Dữ liệu truyền đi| B\n    A -->|FIN| B\n    B -->|ACK + FIN| A\n    A -->|ACK| B" />

1. **SYN**: Client gửi yêu cầu kết nối
2. **SYN-ACK**: Server xác nhận và đồng ý kết nối
3. **ACK**: Client xác nhận đã nhận, kết nối được thiết lập

```python
# Ví dụ TCP server với Python
import socket

# Tạo TCP socket
server = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
server.bind(('0.0.0.0', 8080))
server.listen(5)
print('Server đang lắng nghe tại port 8080...')

while True:
    client_socket, address = server.accept()
    print(f'Kết nối mới từ {address}')

    data = client_socket.recv(1024)
    print(f'Dữ liệu nhận: {data.decode()}')

    client_socket.send(b'Đã nhận dữ liệu thành công!')
    client_socket.close()
```

### UDP -- Nhanh chóng

UDP gửi dữ liệu mà không cần thiết lập kết nối trước. Không đảm bảo dữ liệu đến đích hay đúng thứ tự, nhưng nhanh hơn TCP rất nhiều.

```python
# Ví dụ UDP server
import socket

udp_server = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
udp_server.bind(('0.0.0.0', 9090))
print('UDP server đang lắng nghe...')

while True:
    data, addr = udp_server.recvfrom(1024)
    print(f'Nhận từ {addr}: {data.decode()}')
    udp_server.sendto(b'Pong!', addr)
```

## DNS -- Hệ thống phân giải tên miền

DNS (Domain Name System) chuyển đổi tên miền (ví dụ: google.com) thành địa chỉ IP (ví dụ: 142.250.80.46) để máy tính có thể kết nối.

<Diagram chart="graph LR\n    A[Trình duyệt\ngoogle.com?] --> B[DNS Resolver\nISP Cache]\n    B --> C[Root Name Server\n. root]\n    C --> D[TLD Name Server\n.com]\n    D --> E[Authoritative Server\ngoogle.com]\n    E -->|142.250.80.46| B\n    B -->|142.250.80.46| A" />

```bash
# Truy vấn DNS
nslookup google.com

# Xem chi tiết bản ghi DNS
dig google.com

# Các loại bản ghi DNS phổ biến
dig google.com A       # Địa chỉ IPv4
dig google.com AAAA    # Địa chỉ IPv6
dig google.com MX      # Mail server
dig google.com CNAME   # Alias
dig google.com TXT     # Text record (SPF, DKIM)
```

## HTTP và HTTPS

HTTP (HyperText Transfer Protocol) là giao thức chính để truyền tải dữ liệu trên web.

### Cấu trúc HTTP Request

```
GET /api/users HTTP/1.1
Host: example.com
Accept: application/json
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
```

### Cấu trúc HTTP Response

```
HTTP/1.1 200 OK
Content-Type: application/json
Content-Length: 128

{"users": [{"id": 1, "name": "User A"}]}
```

### Các HTTP Methods phổ biến

| Method | Mục đích | Idempotent |
|--------|----------|------------|
| GET | Lấy dữ liệu | Có |
| POST | Tạo dữ liệu mới | Không |
| PUT | Cập nhật toàn bộ | Có |
| PATCH | Cập nhật một phần | Không |
| DELETE | Xóa dữ liệu | Có |

### HTTPS -- HTTP bảo mật

HTTPS sử dụng TLS/SSL để mã hóa dữ liệu truyền giữa client và server:

<Diagram chart="graph LR\n    A[Client] -->|1. Client Hello| B[Server]\n    B -->|2. Server Hello + Certificate| A\n    A -->|3. Verify Certificate\nTạo Session Key| A\n    A -->|4. Encrypted Data| B\n    B -->|5. Encrypted Data| A" />

<Callout type="warning">Luôn sử dụng HTTPS cho mọi ứng dụng web, đặc biệt khi xử lý dữ liệu nhạy cảm như mật khẩu, thông tin thanh toán. HTTPS không chỉ mã hóa dữ liệu mà còn xác thực danh tính server, chống tấn công man-in-the-middle.</Callout>

## HTTP/2 và HTTP/3

### HTTP/2
- **Multiplexing**: Nhiều request/response đồng thời trên một kết nối TCP
- **Header compression**: Giảm kích thước header với HPACK
- **Server Push**: Server có thể gửi tài nguyên trước khi client yêu cầu

### HTTP/3
- Sử dụng **QUIC** (trên UDP) thay vì TCP
- Giảm thời gian thiết lập kết nối
- Tốt hơn cho mạng không ổn định (mobile, Wi-Fi công cộng)

<Callout type="tip">Hầu hết các web server và CDN hiện đại đều hỗ trợ HTTP/2. HTTP/3 đang dần được hỗ trợ rộng rãi. Bạn có thể kiểm tra protocol đang dùng bằng Developer Tools trong trình duyệt (tab Network, cột Protocol).</Callout>

## Ứng dụng thực tế: Tìm hiểu một request web

Khi bạn gõ `https://example.com` vào trình duyệt, đây là những gì xảy ra:

1. **DNS Resolution**: Trình duyệt hỏi DNS server để lấy địa chỉ IP của example.com
2. **TCP Handshake**: Thiết lập kết nối TCP 3-way handshake với server
3. **TLS Handshake**: Thiết lập kết nối mã hóa TLS/SSL
4. **HTTP Request**: Gửi HTTP GET request đến server
5. **Server xử lý**: Server xử lý request và trả về response
6. **Render**: Trình duyệt nhận HTML, tải CSS/JS, và hiển thị trang

```javascript
// Theo dõi thời gian của từng giai đoạn
const timing = performance.getEntriesByType('navigation')[0];

console.log('DNS lookup:', timing.domainLookupEnd - timing.domainLookupStart, 'ms');
console.log('TCP connect:', timing.connectEnd - timing.connectStart, 'ms');
console.log('TLS handshake:', timing.secureConnectionStart > 0
  ? timing.connectEnd - timing.secureConnectionStart : 'N/A', 'ms');
console.log('Request + Response:', timing.responseEnd - timing.requestStart, 'ms');
console.log('DOM loaded:', timing.domContentLoadedEventEnd - timing.navigationStart, 'ms');
```
