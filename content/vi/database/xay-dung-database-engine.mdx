# Xây Dựng Database Engine Đơn Giản: Hiểu Cách MySQL và SQLite Hoạt Động

Mỗi ngày bạn dùng `SELECT`, `INSERT`, `UPDATE` — nhưng bạn đã bao giờ tự hỏi chuyện gì xảy ra phía sau? Khi bạn gõ `SELECT * FROM users WHERE age > 25`, database phải phân tích cú pháp SQL, chọn chiến lược tìm kiếm tối ưu, đọc dữ liệu từ disk, lọc kết quả và trả về — tất cả trong vài mili-giây. Bài viết này sẽ mở hộp đen đó ra, và hướng dẫn bạn xây dựng một database engine đơn giản để hiểu sâu cách mọi thứ vận hành.

## Tại Sao Tự Xây Database Engine?

Bạn không cần tự xây database cho production — đã có MySQL, PostgreSQL, SQLite rồi. Nhưng việc tự xây giúp bạn:

- **Hiểu sâu** tại sao index giúp query nhanh hơn
- **Debug tốt hơn** khi gặp vấn đề hiệu năng database
- **Thiết kế tốt hơn** schema và truy vấn
- **Phỏng vấn tự tin** khi được hỏi về database internals

<Callout type="info">
SQLite — database nhúng phổ biến nhất thế giới — có source code khoảng 150.000 dòng C. Nhưng bạn có thể hiểu các nguyên lý cốt lõi và xây phiên bản đơn giản chỉ với vài trăm dòng Python.
</Callout>

## Kiến Trúc Của Một Database Engine

Mỗi hệ quản trị cơ sở dữ liệu (DBMS) đều có các thành phần cốt lõi sau:

<Diagram chart="graph TD\n    A[SQL Query] --> B[SQL Parser]\n    B --> C[AST - Abstract Syntax Tree]\n    C --> D[Query Planner / Optimizer]\n    D --> E[Query Plan]\n    E --> F[Execution Engine]\n    F --> G[Storage Engine]\n    G --> H[(Disk - Data Files)]\n    F --> I[Buffer Pool / Page Cache]\n    I --> G\n    F --> J[Index Manager - B-Tree]\n    F --> K[Transaction Manager - WAL]\n    F --> L[Lock Manager]\n    style B fill:#f9f,stroke:#333\n    style D fill:#bbf,stroke:#333\n    style G fill:#bfb,stroke:#333" />

### 1. SQL Parser

Parser nhận chuỗi SQL và chuyển thành **AST** (Abstract Syntax Tree) — cấu trúc dữ liệu dạng cây biểu diễn câu truy vấn.

```python
# Ví dụ: "SELECT name FROM users WHERE age > 25"
# Được parse thành AST:
ast = {
    "type": "SELECT",
    "columns": ["name"],
    "from": "users",
    "where": {
        "operator": ">",
        "left": {"type": "column", "name": "age"},
        "right": {"type": "literal", "value": 25}
    }
}
```

### 2. Query Planner / Optimizer

Với cùng một câu SQL, có nhiều cách thực thi khác nhau. Optimizer chọn cách tối ưu nhất dựa trên thống kê dữ liệu (statistics), index khả dụng, và cost model.

Ví dụ: `SELECT * FROM orders JOIN users ON orders.user_id = users.id WHERE users.country = 'VN'`

- **Kế hoạch A**: Scan toàn bộ orders → JOIN với users → Filter country
- **Kế hoạch B**: Filter users theo country trước → JOIN với orders (tốt hơn nếu ít user ở VN)

### 3. Storage Engine

Chịu trách nhiệm đọc/ghi dữ liệu lên disk. Đây là nơi "ma thuật" thực sự xảy ra.

### 4. Buffer Pool / Page Cache

Cache các pages từ disk vào RAM. Database đọc/ghi theo đơn vị **page** (thường 4KB hoặc 8KB), không đọc từng byte.

### 5. Transaction Manager và WAL

Đảm bảo ACID — đặc biệt durability thông qua **WAL** (Write-Ahead Logging).

### 6. Lock Manager

Kiểm soát truy cập đồng thời (concurrency), ngăn hai transaction xung đột nhau.

## B-Tree: Cấu Trúc Dữ Liệu Cho Index

### Tại Sao B-Tree Mà Không Phải Binary Tree?

Binary Search Tree tìm kiếm O(log₂ N), nhưng mỗi node chỉ chứa một key — nghĩa là mỗi bước tìm kiếm có thể cần đọc một page mới từ disk. Với 1 triệu records, cần ~20 lần đọc disk — mỗi lần mất ~10ms, tổng cộng 200ms.

**B-Tree** (Balanced Tree, fanout cao) mỗi node chứa hàng trăm keys — một node vừa đúng một page (4KB). Với fanout 200, chỉ cần 3 tầng để chứa 8 triệu records. Chỉ 3 lần đọc disk thay vì 20.

## WAL: Write-Ahead Logging

Khi ghi dữ liệu, database không ghi thẳng vào data file. Thay vào đó, nó ghi vào **WAL** trước — một file append-only ghi lại mọi thay đổi. Nếu hệ thống crash, database có thể đọc WAL và khôi phục trạng thái.

<Diagram chart="graph LR\n    A[Transaction: UPDATE] --> B[Ghi vào WAL]\n    B --> C[Cập nhật Buffer Pool]\n    C --> D[Trả về OK cho client]\n    D -.-> E[Background: Flush dirty pages ra disk]\n    B --> F[(WAL File - tuần tự)]\n    E --> G[(Data Files - ngẫu nhiên)]\n    style B fill:#f96,stroke:#333\n    style F fill:#bfb,stroke:#333" />

<Callout type="warning">
WAL là lý do tại sao database có thể trả về thành công ngay cả khi dữ liệu chưa ghi vào data file chính. Nếu crash xảy ra, quá trình recovery sẽ replay WAL để đảm bảo không mất dữ liệu. Đây chính là cách đảm bảo **Durability** trong ACID.
</Callout>

## Thực Hành: Xây Key-Value Store Bằng Python

Hãy xây một key-value store đơn giản với các tính năng: file-based storage, append-only log, in-memory index, và compaction.

```python
import json
import os
from typing import Optional
from threading import Lock

class SimpleKVStore:
    """
    Key-Value Store đơn giản sử dụng append-only log.
    Tương tự cách Bitcask (dùng bởi Riak) hoạt động.
    """

    def __init__(self, directory: str):
        self.directory = directory
        self.log_file = os.path.join(directory, "data.log")
        self.index: dict[str, int] = {}  # key -> byte offset trong file
        self.lock = Lock()

        os.makedirs(directory, exist_ok=True)
        self._rebuild_index()

    def _rebuild_index(self):
        """Đọc lại log file để xây dựng in-memory index."""
        if not os.path.exists(self.log_file):
            return

        with open(self.log_file, 'r') as f:
            offset = 0
            for line in f:
                entry = json.loads(line.strip())
                if entry['type'] == 'SET':
                    self.index[entry['key']] = offset
                elif entry['type'] == 'DELETE':
                    self.index.pop(entry['key'], None)
                offset = f.tell()

    def set(self, key: str, value: str):
        """Thêm hoặc cập nhật một key-value pair."""
        with self.lock:
            entry = json.dumps({
                'type': 'SET',
                'key': key,
                'value': value
            })
            with open(self.log_file, 'a') as f:
                offset = f.tell()
                f.write(entry + '\n')
                self.index[key] = offset

    def get(self, key: str) -> Optional[str]:
        """Đọc giá trị theo key. O(1) nhờ in-memory index."""
        if key not in self.index:
            return None

        with open(self.log_file, 'r') as f:
            f.seek(self.index[key])
            line = f.readline()
            entry = json.loads(line.strip())
            return entry['value']

    def delete(self, key: str) -> bool:
        """Xóa key bằng cách ghi tombstone."""
        if key not in self.index:
            return False

        with self.lock:
            entry = json.dumps({'type': 'DELETE', 'key': key})
            with open(self.log_file, 'a') as f:
                f.write(entry + '\n')
            del self.index[key]
        return True

    def compact(self):
        """
        Nén log file: chỉ giữ giá trị mới nhất của mỗi key.
        Giảm kích thước file và tăng tốc startup.
        """
        with self.lock:
            compact_file = self.log_file + '.compact'
            new_index = {}

            with open(compact_file, 'w') as out:
                for key, offset in self.index.items():
                    value = self.get(key)
                    if value is not None:
                        entry = json.dumps({
                            'type': 'SET',
                            'key': key,
                            'value': value
                        })
                        new_offset = out.tell()
                        out.write(entry + '\n')
                        new_index[key] = new_offset

            # Atomic swap
            os.replace(compact_file, self.log_file)
            self.index = new_index

    def keys(self) -> list[str]:
        """Liệt kê tất cả keys."""
        return list(self.index.keys())


# === Sử dụng ===
db = SimpleKVStore("./my_database")

# Ghi dữ liệu
db.set("user:1", '{"name": "Thắng", "age": 28}')
db.set("user:2", '{"name": "Linh", "age": 25}')
db.set("user:3", '{"name": "Minh", "age": 30}')

# Đọc dữ liệu
print(db.get("user:1"))  # {"name": "Thắng", "age": 28}

# Cập nhật
db.set("user:1", '{"name": "Thắng", "age": 29}')
print(db.get("user:1"))  # {"name": "Thắng", "age": 29}

# Xóa
db.delete("user:3")
print(db.get("user:3"))  # None

# Compaction - dọn dẹp dữ liệu cũ
db.compact()
print(f"Tổng số keys: {len(db.keys())}")  # 2
```

<Callout type="tip">
Key-value store trên sử dụng mô hình **Bitcask** — append-only log với in-memory hash index. Đây chính là cách Riak database hoạt động. Ưu điểm: ghi cực nhanh (sequential I/O), đọc O(1). Nhược điểm: tất cả keys phải fit trong RAM.
</Callout>

## Từ Key-Value Store Đến Relational Database

Key-value store của chúng ta chỉ hỗ trợ GET/SET/DELETE theo key. Để thành relational database, cần thêm:

1. **SQL Parser**: Phân tích cú pháp SQL thành AST
2. **Schema Management**: Định nghĩa bảng, cột, kiểu dữ liệu
3. **B-Tree Index**: Cho phép tìm kiếm theo range (WHERE age > 25)
4. **Query Executor**: Thực thi JOIN, GROUP BY, ORDER BY
5. **Transaction Support**: BEGIN, COMMIT, ROLLBACK với ACID
6. **Concurrency Control**: Nhiều client truy cập đồng thời

```python
# Ví dụ đơn giản: thêm SQL parser lên trên key-value store
class SimpleSQL:
    def __init__(self, kv_store: SimpleKVStore):
        self.kv = kv_store
        self.schemas = {}  # table_name -> [column_names]

    def create_table(self, table: str, columns: list[str]):
        self.schemas[table] = columns
        self.kv.set(f"__schema:{table}", json.dumps(columns))

    def insert(self, table: str, values: dict):
        # Tạo auto-increment ID
        counter_key = f"__counter:{table}"
        current = self.kv.get(counter_key)
        new_id = int(current or 0) + 1
        self.kv.set(counter_key, str(new_id))

        # Lưu record
        self.kv.set(f"{table}:{new_id}", json.dumps(values))
        return new_id

    def select_by_id(self, table: str, record_id: int) -> Optional[dict]:
        result = self.kv.get(f"{table}:{record_id}")
        return json.loads(result) if result else None

# Sử dụng
sql = SimpleSQL(SimpleKVStore("./sql_db"))
sql.create_table("users", ["name", "age", "email"])
uid = sql.insert("users", {"name": "Thắng", "age": 28, "email": "thang@example.com"})
print(sql.select_by_id("users", uid))
```

## Tổng Kết

Database engine là một trong những phần mềm phức tạp nhất mà con người tạo ra. Nhưng khi tách nhỏ từng thành phần — parser, optimizer, storage engine, buffer pool, B-Tree, WAL — mỗi phần đều có thể hiểu được. Key-value store mà chúng ta xây dựng ở trên chỉ có khoảng 100 dòng code, nhưng nó minh họa nguyên lý cốt lõi của mọi database: append-only log cho durability, in-memory index cho tốc độ đọc, và compaction cho quản lý dung lượng. Từ nền tảng này, bạn có thể tiếp tục khám phá B-Tree, MVCC, query optimization — và sẽ không bao giờ nhìn `SELECT * FROM users` theo cách cũ nữa.
