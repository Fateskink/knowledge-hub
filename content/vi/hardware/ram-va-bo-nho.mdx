# RAM và Bộ nhớ - Hệ thống phân cấp bộ nhớ máy tính

Khi bạn mở 20 tab Chrome và máy tính bắt đầu chậm, đó là lúc bạn chiến đấu với **giới hạn bộ nhớ**. RAM (Random Access Memory) là một trong những thành phần quyết định hiệu suất máy tính, nhưng nó chỉ là một phần trong một hệ thống bộ nhớ phức tạp. Bài viết này sẽ giúp bạn hiểu toàn bộ bức tranh.

## RAM hoạt động như thế nào?

RAM là bộ nhớ **tạm thời** (volatile) - nó lưu trữ dữ liệu chỉ khi có điện. Tắt nguồn điện, mọi dữ liệu trong RAM sẽ mất. Đây là nơi hệ điều hành, ứng dụng đang chạy, và dữ liệu đang xử lý được lưu trữ để CPU truy cập nhanh.

### Tại sao gọi là "Random Access"?

"Random Access" có nghĩa là CPU có thể truy cập **bất kỳ ô nhớ nào** trực tiếp mà không cần đọc tuần tự từ đầu. Khác với băng từ (tape) phải tua đến vị trí cần đọc, RAM cho phép nhảy thẳng đến địa chỉ bất kỳ trong thời gian như nhau.

## DRAM vs SRAM

Có 2 loại RAM chính, mỗi loại có cấu trúc và ứng dụng khác nhau:

### DRAM (Dynamic RAM) - RAM động

DRAM lưu trữ mỗi bit bằng **1 tụ điện (capacitor) + 1 transistor**:

```
Cấu trúc tế bào DRAM:

    Word Line (chọn hàng)
        |
    ┌───┴───┐
    │       │
    │  MOSFET│──── Bit Line (đọc/ghi dữ liệu)
    │       │
    └───┬───┘
        │
    ┌───┴───┐
    │       │
    │  Tụ   │  <- Tụ điện lưu trữ 1 bit
    │  điện │     Sạc điện = 1, hết điện = 0
    │       │
    └───┬───┘
        │
       GND
```

- Tụ điện **có điện** = bit 1, **hết điện** = bit 0.
- Vấn đề: tụ điện bị rò điện theo thời gian, nên phải được **làm tươi (refresh)** hàng nghìn lần mỗi giây.
- Đó là lý do gọi là "Dynamic" - dữ liệu phải được cập nhật liên tục.

<Callout type="info">Mỗi tế bào DRAM chỉ cần 1 transistor + 1 tụ điện, nên rất nhỏ gọn và rẻ. Đây là lý do DRAM được dùng làm RAM chính của máy tính - có thể đạt được dung lượng lớn (16GB, 32GB, 64GB) với giá hợp lý.</Callout>

### SRAM (Static RAM) - RAM tĩnh

SRAM lưu trữ mỗi bit bằng **6 transistor** theo cấu trúc flip-flop:

```
Cấu trúc tế bào SRAM (6 transistor):

    Word Line
    ┌───┴───────────┴───┐
    │                   │
   T5                  T6    <- Transistor truy cập
    │                   │
    ├───┐       ┌───────┤
    │   │       │       │
   T1   T3     T2      T4   <- 2 cặp inverter chéo
    │   │       │       │
    BL  └───┬───┘      BL*  <- Bit Line và Bit Line đảo
            │
           GND
```

- Không cần làm tươi, dữ liệu ổn định khi có điện.
- Nhanh hơn DRAM nhiều lần.
- Nhưng tốn gấp 6 lần diện tích (6 transistor vs 1), nên đắt và tốn điện hơn.

<Callout type="tip">DDR5 chia 1 kênh 64-bit thành 2 kênh 32-bit độc lập, giúp tăng hiệu quả truy cập (nhờ 2 lệnh đọc/ghi chạy song song). Điều này đặc biệt có lợi cho các tác vụ đa luồng.</Callout>

```
DDR4-3200: 3200 MT/s x 8 bytes = 25.6 GB/s
DDR5-6400: 6400 MT/s x 8 bytes = 51.2 GB/s (gấp đôi!)
DDR5-8400: 8400 MT/s x 8 bytes = 67.2 GB/s
```

## Hệ thống phân cấp Bộ nhớ (Memory Hierarchy)

Đây là khái niệm cốt lõi: **bộ nhớ nhanh thì nhỏ và đắt, bộ nhớ lớn thì chậm và rẻ**. Máy tính giải quyết mâu thuẫn này bằng hệ thống phân cấp:

```
So sánh trực quan (nếu Register là 1 giây):

Register:  1 giây         (lấy sách trên bàn)
L1 Cache:  2 giây         (lấy sách trên kệ cạnh bàn)
L2 Cache:  10 giây        (đi đến kệ sách trong phòng)
L3 Cache:  30 giây        (đi đến phòng bên cạnh)
RAM:       100 giây       (đi xuống tầng 1)
SSD:       2.8 giờ        (đi đến thư viện thành phố)
HDD:       11.6 ngày      (đặt mua sách từ nước ngoài!)
```

<Callout type="warning">Sự chênh lệch tốc độ giữa các cấp bộ nhớ là KHỔNG LỒ. RAM nhanh hơn HDD khoảng 100,000 lần. Đây là lý do tại sao cache và RAM là yếu tố quyết định hiệu suất máy tính trong nhiều trường hợp.</Callout>

### Nguyên lý Locality (Tính cục bộ)

Hệ thống phân cấp hoạt động hiệu quả nhờ 2 nguyên lý:

- **Temporal Locality** (Cục bộ thời gian): Dữ liệu vừa được truy cập có khả năng cao sẽ được truy cập lại sớm. Ví dụ: biến đếm trong vòng lặp.
- **Spatial Locality** (Cục bộ không gian): Dữ liệu gần dữ liệu vừa truy cập có khả năng cao sẽ được truy cập. Ví dụ: các phần tử liên tiếp trong mảng.

```python
# Ví dụ về locality ảnh hưởng hiệu suất

# Tốt - Spatial Locality (truy cập tuần tự)
matrix = [[0]*1000 for _ in range(1000)]
for i in range(1000):
    for j in range(1000):
        matrix[i][j] = i + j  # Truy cập liên tiếp trong bộ nhớ

# Kém - Spatial Locality kém (truy cập nhảy cóc)
for j in range(1000):
    for i in range(1000):
        matrix[i][j] = i + j  # Nhảy giữa các hàng, cache miss nhiều
```

## Virtual Memory - Bộ nhớ ảo

Khi RAM không đủ, hệ điều hành sử dụng **virtual memory** - mượn một phần ổ cứng làm "RAM mở rộng".

### Cơ chế Paging

Bộ nhớ được chia thành các khối cố định gọi là **page** (thường 4KB):

```
Virtual Memory (chương trình thấy):
┌──────────────────────────┐
│ Page 0: Code chương trình│──┐
│ Page 1: Dữ liệu          │──┤── Mapping
│ Page 2: Stack             │──┤
│ Page 3: Heap              │──┤
│ ...                       │  │
│ Page N: Thư viện          │──┘
└──────────────────────────┘
          |
     Page Table (bảng ánh xạ)
          |
    ┌─────┴──────┐
    v            v
Physical RAM   Swap (SSD/HDD)
┌──────────┐  ┌──────────┐
│ Page 0   │  │ Page 3   │ <- Page ít dùng được
│ Page 1   │  │ Page N   │    chuyển ra ổ cứng
│ Page 2   │  │          │
└──────────┘  └──────────┘
```

- Mỗi chương trình "tưởng" nó có toàn bộ không gian bộ nhớ riêng.
- Hệ điều hành ánh xạ (map) các trang ảo sang trang vật lý trong RAM.
- Khi RAM đầy, trang ít dùng được chuyển ra ổ cứng (**swap/page file**).
- Khi cần lại, trang được đọc từ ổ cứng vào RAM (**page fault**).

<Callout type="danger">Khi máy tính phải swap liên tục (gọi là "thrashing"), hiệu suất giảm thảm hại vì ổ cứng chậm hơn RAM hàng nghìn lần. Đây là lý do máy tính "đơ" khi mở quá nhiều ứng dụng với ít RAM. Giải pháp: tăng RAM hoặc đóng bớt ứng dụng.</Callout>

### TLB (Translation Lookaside Buffer)

Để tránh việc tra Page Table (nằm trong RAM) mỗi lần truy cập bộ nhớ, CPU có **TLB** - một bộ nhớ đệm nhỏ lưu các ánh xạ trang được dùng gần đây. TLB hit chỉ mất vài chu kỳ, trong khi TLB miss có thể mất hàng trăm chu kỳ.

## Mẹo thực tế

### Khi nào cần nâng cấp RAM?

- **8GB**: Đủ cho sử dụng cơ bản, lướt web, văn phòng.
- **16GB**: Phù hợp lập trình, chơi game, sử dụng đa nhiệm.
- **32GB**: Cần cho video editing, chạy máy ảo, lập trình nặng.
- **64GB+**: Data science, 3D rendering, server.

### Cách kiểm tra RAM trên máy

```bash
# Windows
wmic memorychip get capacity, speed, memorytype

# macOS
system_profiler SPMemoryDataType

# Linux
free -h
sudo dmidecode -t memory
```

### Dual Channel

Luôn lắp **2 thanh RAM giống nhau** để chạy Dual Channel, tăng băng thông gấp đôi:

```
1 thanh 16GB: 25.6 GB/s (Single Channel)
2 thanh 8GB:  51.2 GB/s (Dual Channel) - Nhanh gấp đôi!
```

## Tóm tắt

Hệ thống bộ nhớ là một trong những khía cạnh phức tạp và quan trọng nhất của máy tính. Từ tế bào DRAM nhỏ bé (1 transistor + 1 tụ điện) đến hệ thống phân cấp nhiều cấp, tất cả được thiết kế để giải quyết một bài toán cơ bản: **làm sao cung cấp dữ liệu cho CPU nhanh nhất có thể với chi phí hợp lý**.

Hiểu về bộ nhớ giúp bạn đưa ra quyết định tốt hơn khi nâng cấp phần cứng, tối ưu code, và xử lý các vấn đề hiệu suất.
